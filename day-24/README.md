# День 24 — цитаты, источники и проверка ответа

RAG по README этого проекта с проверкой каждого утверждения. Поиск возвращает
кандидатов, порог отбирает контекст, DeepSeek формирует утверждения с цитатами.
Сервер проверяет цитаты по найденным чанкам; отдельный вызов DeepSeek проверяет,
поддерживает ли цитата смысл утверждения. Интерфейс показывает эти этапы.

## Запуск

Нужны Python 3.12, Node.js 20+ и Git. Из каталога `day-24`:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
npm --prefix frontend ci
cp .env.example .env
# Заполните DEEPSEEK_API_KEY только в локальном .env
npm run dev
```

Интерфейс: [localhost:5190](http://127.0.0.1:5190/).
API: [localhost:5023/docs](http://127.0.0.1:5023/docs).
Остановка — `Ctrl+C`. Оба сервера слушают только localhost.

## Документы и индекс

Источник — отслеживаемые Git корневой README и README дней 01–20.
PDF, `.env`, локальные отчёты, wiki и README RAG-дней не входят в корпус.
Общая библиотека Day 21 обеспечивает загрузку Markdown, две стратегии
chunking, многоязычные 384-мерные FastEmbed-векторы и SQLite. Запускать сервер
Day 21 не требуется. Day 24 имеет собственный `data/index.sqlite`.

Нажмите «Построить индекс», если его нет или документы изменились.
Первое использование скачивает модель в `.cache/fastembed`; последующий поиск
локальный. SHA-256 списка путей и байтов README определяет актуальность.
Индекс сохраняется после перезапуска. Изменённый корпус требует пересборки.

## Контракт ответа

Модель возвращает JSON со статусом и утверждениями. У каждого утверждения
есть текст, `chunk_id` и цитата. Один чанк может подтверждать несколько
разных утверждений; точные дубликаты утверждений отклоняются. Ответ собирается из этих проверенных утверждений.
`source` и `section` берутся сервером из выбранного чанка, а не из выдуманного
моделью имени файла. Цитата должна дословно присутствовать в этом чанке;
различия пробелов допускаются. После порога и top-K к опорным чанкам добавляются предыдущий и следующий
фрагменты того же документа и стратегии; при structure — того же раздела.
Этот ограниченный контекст хранится в `evidence_chunks`, с устранением
повторных ID. У соседей нет собственной cosine-оценки: роль `neighbor` и
`anchor_chunk_id` показывают основание включения. Допускаются цитаты только
из этого явно предоставленного списка и только по настоящему ID своего чанка.
Подмена ID даже при дословной цитате не принимается. Максимум — три чанка
доказательств на один опорный; фактическое число обычно меньше из-за пересечений.

Затем независимый вызов модели проверяет связь «утверждение → цитата» с учётом полного чанка и соседнего
контекста, чтобы учитывать обрезанное отрицание или условия.
В Day 24 утверждения со статусом `unsupported` или `uncertain` исключаются из
ответа. Если часть утверждений подтверждена, публикуется только эта часть с
её источниками и цитатами: `partial=true`, причина `partially_grounded`.
Отклонённые утверждения и причины доступны отдельно в `rejected_claims`;
все исходные проверки сохранены в `validation.checks`, а
`published_claim_indices` связывает опубликованные утверждения с их исходными
индексами. `semantic_status=supported` относится только к опубликованной части
и не означает полноту ответа. Если не подтверждено ни одного утверждения,
возвращается «Не знаю». Выдуманный ID, неточная цитата или неверный формат
по-прежнему отклоняют весь ответ до смысловой проверки. Модельная проверка
может ошибаться: статус проверки не означает доказанную истинность. Проверка
точного текста цитаты и проверка её смысла показаны отдельно.

Если все найденные оценки ниже порога, контекст пуст, модель признаёт отсутствие
ответа или не подтверждено ни одного утверждения, приложение сообщает **«Не знаю»** и
просит уточнение. Подтверждённые источники отсутствуют — это явно показано,
вымышленных цитат не создаётся. Слабый контекст не отправляется на генерацию.
Ошибка API или таймаут показаны отдельно и не считаются ответом «Не знаю».
Cosine не является вероятностью правильности: высокий score не гарантирует,
что нужный факт есть в отрывке.

Явный номер дня в вопросе ограничивает источники перед cosine-поиском, как в
Day 23. Без номера дня поиск идёт по всему корпусу. Порог, стратегия и оба
top-K фиксируются в результате каждого запроса. Контрольные ожидания не
используются алгоритмом поиска или проверяющей моделью.

## Демонстрация без голоса

1. Покажите корпус, параметры поиска и сборку индекса.
2. Выберите контрольный вопрос и отправьте его.
3. Раскройте кандидатов: источник, раздел, ID, score и решение порога.
4. Покажите утверждения и цитаты, результат точной и смысловой проверки.
5. Покажите итоговый ответ с источниками. При отказе — причину и уточнение.
6. Повысите порог, повторите вопрос и покажите «Не знаю» при пустом контексте.
7. Запустите десять контрольных вопросов, покажите прогресс и итоговые счётчики,
   скачайте JSON. Отметку ручной проверки смысла отделяйте от решения модели.

## Контрольные вопросы и ограничения

`questions.json` содержит десять вопросов по проекту, ожидания и источники.
Для каждого ответа проверяются наличие источников, цитат, точное совпадение
цитаты и решение смыслового verifier. Отказы и ошибки учитываются отдельно:
наличие цитат у успешных ответов не скрывает количество отказов.

Генерация и смысловая проверка могут требовать два основных вызова на вопрос.
Слабый контекст не требует вызовов. HTTP-повторы подключения/429/503 могут
увеличить число запросов; таймаут ожидания ответа не повторяется автоматически.
Экспорты и данные проверки локальные; fake-модель тестов не подтверждает качество
реальных ответов. Вопросы и выбранные README-фрагменты передаются DeepSeek.
Ключ остаётся на backend и не входит в результат или export.

`.env`, базы, модельный кэш, виртуальное окружение, сборка и экспорты исключены
из Git. Это локальный учебный стенд, без многопользовательской авторизации.

Тесты отличают точную цитату с неверным смыслом, выдуманный ID,

## Результат живой проверки — 3 октября 2026

Это исторический прогон до включения публикации частично подтверждённых
ответов. Его счётчики не описывают результаты нового режима.

Собственный индекс: 21 README, 180 разделов, 23 291 слово (46,58 условной
страницы), 488 fixed / 526 structure чанков, 384 измерения. Параметры проверки:
structure, 12 → 5 опорных чанков, порог 0,45 и ограниченное окно соседей.

Из десяти вопросов получено 8 ответов и 2 «Не знаю», ошибок провайдера — 0.
Все восемь опубликованных ответов имеют источники и дословные цитаты;
verifier признал их поддержанными. Два ответа отклонены по смыслу, несмотря
на дословные цитаты. При пороге 1 получен отказ без генерации модели.

Ответы дополнительно прочитаны coding-агентом: у вопросов про summary,
preflight и cron раскрыты не все ожидаемые детали. Это не 80% доказанной
фактической правильности и не оценка полноты ответа. Первоначальная ошибка
про localStorage выявлена живой проверкой и учтена в контекстном извлечении;
модельная смысловая проверка всё ещё может ошибаться или излишне отказывать.

Локальные результаты: `data/benchmark-live.json` и
`data/benchmark-live-reviewed.json`. Второй файл содержит отдельные заметки
coding-агента, а не отметки пользователя. Результаты не коммитятся.
Проверено: 32 backend-теста, 7 frontend-тестов, production build, SQLite
integrity check и запуск обоих серверов. Визуальная проверка в браузере не
выполнялась из-за ограничения инструмента.

Фоновые прогоны хранятся в памяти backend и исчезают после перезапуска;
сохраните export. Индекс остаётся на диске. Отмена действует между вопросами:
уже отправленный HTTP-запрос может завершиться и быть тарифицирован.

### Проверка исправления частичного ответа

Вопрос «Как в дне 7 сохраняется контекст диалога после перезапуска?»
воспроизвёл излишний отказ: поиск нашёл данные, но одно широкое утверждение
получило цитату из обрезанного предложения и verifier отклонил весь ответ.
После включения отбора подтверждённых утверждений живой повтор вернул
частичный ответ: хранение сессий/сообщений в `data/context.sqlite3` и загрузка
истории перед каждым запросом. Два утверждения опубликованы с дословными
цитатами из `day-07/README.md`; третье исключено. Это проверка одного вопроса,
а не новый результат полного контрольного набора. Проверено 38 backend-тестов,
7 frontend-тестов и production build.
