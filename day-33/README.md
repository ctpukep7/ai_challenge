# День 33 — ассистент поддержки пользователей

Мини-сервис поддержки AI Challenge: справка в RAG, вымышленные пользователи
и тикеты в JSON через настоящий MCP stdio. Один вопрос получает разные
рекомендации в зависимости от наблюдений выбранного тикета.

## Установка и запуск

Из корня репозитория, Python 3.12 и Node.js 22+:

```bash
python3.12 -m venv .assistant-venv
.assistant-venv/bin/pip install -r packages/assistant_core/requirements.lock.txt
.assistant-venv/bin/pip install --no-build-isolation -e packages/assistant_core
npm --prefix day-33/frontend ci
cp day-33/.env.example day-33/.env
```

Если окружение новой недели уже настроено для Day31, повторно создавать его
не нужно. В локальном `.env` задайте `DEEPSEEK_API_KEY`. Не вводите ключ в чат.
Из папки `day-33` выполните `npm run dev`: API — `http://127.0.0.1:5032`,
интерфейс — `http://127.0.0.1:5198`. Ctrl+C завершает оба процесса.
Для production: `npm run build`, затем `npm start`; интерфейс доступен на 5032.
Сервис предназначен для локальной учебной демонстрации, публичная CRM не нужна.

FastEmbed читает существующий кэш `day-21/.cache/fastembed` (multilingual
MiniLM-L12-v2). При переносе скопируйте этот кэш или задайте
`ASSISTANT_EMBED_CACHE` в `.env`. Автоматического скачивания модели нет.
Новые веса LLM не нужны; ответы генерирует DeepSeek. Нажмите «Построить индекс»
перед первым вопросом. У каждого приложения недели собственная SQLite-база.

## Источники и контекст

Корпус строго ограничен тремя публичными документами:
`docs/support/faq.md`, `docs/support/troubleshooting.md`,
`docs/support/privacy.md`. Общая разработческая документация, исходники,
README прежних дней, wiki, Memory Bank и `.env` не индексируются.
Индекс `data/index.sqlite` сохраняет путь, строки, раздел, SHA256 и текст
фрагмента; чанки не превышают 126 содержательных токенов embedding-модели.
Поиск выбирает cosine top12 → порог 0.35 → до 5 источников. Наблюдения тикета
уточняют поисковый запрос. После изменения документов требуется пересборка.

`fixtures/support.json` содержит только вымышленные данные. MCP-инструменты:

- `list_tickets()` — список учебных тикетов.
- `get_ticket(ticket_id)` — выбранный тикет.
- `get_ticket_user(ticket_id)` — пользователь, связанный именно с этим тикетом.

Произвольного запроса пользователя по user ID нет. Сервер проверяет отношения
в JSON и соответствие пользователя выбранному тикету. MCP не получает API-ключ
в окружении, ничего не записывает, не меняет токены и не отправляет сообщения.
На каждом вопросе сервер заново читает список и выбранные записи через MCP;
при сбое запрос завершается ошибкой, старые сведения не подставляются.

DeepSeek получает только выбранный тикет с его пользователем, найденную справку,
вопрос и до четырёх полных пар истории текущего тикета. История имеет ticket_id;
backend отклоняет смешанную или немаркированную историю. Интерфейс очищает
беседу при переключении и игнорирует поздний ответ прежнего тикета.
История хранится только в памяти вкладки, не в SQLite и не в localStorage.

Ответ отделяет наблюдения MCP от документальных рекомендаций. Для каждого
документального утверждения проверяются ID источника и точная цитата.
Это проверка происхождения, а не доказательство смысловой истинности.
Недостаток данных требует уточнения; типичная причина не считается диагнозом.
Под ответом доступны полные фрагменты справки и реальные JSON MCP-вызовов.
HTML и Markdown модели не исполняются. Модель выбирает `quote_id` из каталога
точных фрагментов, построенного host. Host разворачивает выбранный ID в цитату,
проверяет соответствие источника и отсутствие противоречащего `quote`, затем
применяет общую строгую проверку цитат. Старый формат с точной цитатой поддержан.
При ошибке структуры или цитаты допускается максимум одна дополнительная
платная попытка исправления ответа с тем же контекстом. Неуспех завершается 502.
Ошибки сети и провайдера не повторяются. API показывает `validation` с полями
`repair_attempted` и `repaired`; интерфейс отмечает успешную дополнительную попытку.

## API

- `GET /api/tickets` — список тикетов и трасса MCP.
- `GET /api/index` — ready/stale/documents/chunks.
- `POST /api/index/build` — атомарное обновление индекса.
- `POST /api/support/ask` — `{ticket_id, question, history}`;
  каждый элемент истории — `{ticket_id, role, content}`, максимум 4 пары.
  Ответ: status (`answered` или `unknown`), answer, ticket_id, sources,
  context (`ticket`, `user`), trace, index. Источники содержат path, строки,
  полный текст, цитату, раздел, SHA256 и score.

Неверный ввод и смешанная история: 422; неизвестный тикет: 404;
индекс отсутствует/устарел или запрос уже выполняется: 409;
сбой DeepSeek: 502; ошибка MCP/локальной модели: 503.
Одновременно выполняется один запрос генерации или индексации.

## Проверка

Из `day-33`:

```bash
npm test
npm run build
```

Backend-тесты проверяют настоящий MCP subprocess и discovery, неизвестный тикет,
недопустимый user_id, отношения JSON, изоляцию истории даже при ручном запросе,
состав передаваемого модели контекста, ссылки, ошибки и устаревший индекс.
Frontend-тесты проверяют ограниченную историю, переключение, поздний ответ,
ошибку прежнего тикета, дублирование отправки и восстановление вопроса.

Ручная приёмка: задайте «Почему не работает авторизация?» каждому тикету:

- `AUTH-101`: HTTP401 и сообщение об устаревшем токене; справка предлагает
  получить действующий токен у владельца, не передавая его поддержке.
- `TLS-102`: ошибка доверия сертификату до запроса авторизации; требуется
  проверка публичного сертификата и адреса, а не отключение TLS.
- `NET-103`: соединение отклонено до загрузки страницы; проверяются сервер,
  сеть и адрес, причина без проверки остаётся предположением.
- `INFO-104`: данных недостаточно; нужны безопасный код ошибки и шаги.

У неполного тикета есть явный флаг `needs_details`. На первом обращении host
запрашивает безопасные уточнения со статусом unknown, не вызывает генерацию
диагноза и не выдаёт это уточнение за ответ модели. Последующие сообщения
с историей проходят RAG и DeepSeek: пользователь может добавить недостающие
наблюдения без изменения read-only JSON.

При переключении во время ответа прежняя беседа не должна появиться в новой.
Enter отправляет вопрос, Shift+Enter добавляет строку. Проверьте источники FAQ,
отдельный блок наблюдений и реальные MCP-вызовы. Живые DeepSeek-запросы и
браузерная проверка выполняются отдельно от автоматических offline-тестов.
Не используйте в демонстрации настоящие пароли, API-ключи и данные клиентов.
