# День 26 — запуск локальной LLM

В интерактивном CLI-чате вы задаёте свои вопросы и продолжаете общение
с локальной моделью. Приложение отправляет запросы в Ollama на этом ноутбуке
через HTTP и показывает ответы и реальные метрики генерации. Модель — `qwen3:4b-instruct-2507-q4_K_M`. Облачных провайдеров
и API-ключей в приложении нет. Интерфейс — терминал; отдельный веб-чат реализован в [Day27](../day-27/README.md).


## Соответствие заданию Day26

- **Локальный запуск:** native Ollama и веса Qwen находятся на ноутбуке;
  сервер запускается через `./run-server.sh`, облачного fallback нет.
- **CLI и HTTP:** `cli.py check/ask/chat` и прямой `/api/chat` описаны ниже.
- **Простой ответ и три уровня сложности:** живой прогон 10 октября содержит
  три непустых ответа: объяснение, расчёт и рекомендацию. Это генерация,
  а не только успешный health-check.
- **Результат:** локальная модель отвечает; ошибки сложных задач описаны ниже.
- **Видео + код:** код и инструкции находятся в этой папке. Для видео покажите
  `check` и три вопроса разной сложности с ответами. Наличие и содержание
  итогового видео этой перепроверкой не подтверждаются; видео не входит в Git.

все 47 тестов прошли. Числа расхода диска и скорости ниже относятся

## Общайтесь со своими вопросами

Если Ollama уже запущена, переходите сразу к `python3 cli.py chat`.
Иначе при установленной модели запустите сервер в первом терминале из `day-26`:

```sh
./run-server.sh
```

Во втором терминале из `day-26`:

```sh
python3 cli.py check
python3 cli.py chat
```

Введите свой вопрос после `Вы:`. Модель отвечает, показывает полный ответ,
время и число токенов. Можно задавать уточнения: она получает предыдущие
вопросы и ответы. Для задания отправьте минимум три **собственных запроса**
разной сложности и оцените полученные ответы. Готовая `demo` для этого не нужна.

Команды внутри чата:

- `/help` — показать команды и клавиши редактора.
- `/prompts` — показать обозначения готовых вопросов.
- `/clear` — очистить историю и начать новый разговор.
- `/exit` — выйти; EOF и `Ctrl+C` на вводе также завершают чат с кодом `0`.

История хранится только в RAM и исчезает после выхода. Чат ничего не сохраняет,
не принимает `--json` и `--output`. В памяти остаются до четырёх последних
полных пар вопрос/ответ; перед запросом суммарный текст истории и нового вопроса
ограничивается 3000 UTF-8 байт. Старые пары удаляются целиком с уведомлением.
Это консервативный текстовый бюджет, а не точный подсчёт токенов модели.
Слишком длинный текущий вопрос отклоняется до отправки; сократите его и введите
снова. Текущий вопрос автоматически не обрезается.

После ошибки API или пустого ответа диалог продолжается, история не меняется.
Автоматических повторов нет: повторить вопрос можно самостоятельно. `Ctrl+C`
во время генерации завершает клиент с кодом `130`; сервер может ещё завершать
ответ. Выход из чата не останавливает Ollama; модель выгружается после минуты
простоя. Если сервер запущен вами в первом терминале, его можно остановить
через `Ctrl+C` для освобождения ресурсов.

Живая проверка интерактивного чата выполнена 10 октября 2026: модель учла
название тестового проекта из предыдущего сообщения, правильно ответила на
уточнение и вычислила 1224 ₽. После `/clear` ответила «Не знаю» на вопрос о
названии, которого уже не было в текущем контексте. `/help`, неизвестная команда
и `/exit` также проверены. Использовались только синтетические тестовые сообщения.

## Подстановка и редактирование вопросов

В обычном терминале `python3 cli.py chat` включает редактор ввода.
Введите обозначение и нажмите **Tab**:

- `/1` — вопрос о четырёх свечах из Day03.
- `/2` — переправа кошки, собаки и морской свинки из Day05.
- `/3` — два предложения без буквы «а» из Day05.
- `/4` — слова стихотворения в алфавитном порядке из Day05.

Обозначение заменится полным вопросом. Его можно изменить; **Enter отправит
готовый текст**. Enter на самом обозначении тоже только подставляет вопрос:
для отправки потребуется ещё одно нажатие. Подстановка не обращается к модели.
Код должен занимать всё поле; внутри обычного вопроса он не заменяется.

Клавиши редактора:

- **← / →** — перемещение по символам.
- **Ctrl+← / Ctrl+→** — перемещение по словам. Альтернатива: **Esc, затем b / f**.
  Option+← / → также работает, если терминал передаёт Meta; macOS может
  перехватывать сочетания Control, а Option зависит от настроек терминала.
- **Home / End** или **Ctrl+A / Ctrl+E** — начало / конец текущей строки.
- **Ctrl+Home / Ctrl+End** — начало / конец всего вопроса.
- **Esc, затем Enter** или **Ctrl+O** — добавить новую строку.
- **↑ / ↓** — переход между строками многострочного вопроса.

Автоматический перенос длинного текста по ширине терминала не создаёт новую
строку ввода: ↑/↓ и Home/End работают с явными переводами строки. Вставка
нескольких строк через bracketed paste остаётся одним вопросом до отдельного
Enter. Редактор не сохраняет введённые вопросы на диск и не ведёт историю
ввода для повторного выбора стрелками; история беседы с моделью описана выше.
При вводе через pipe или без установленных зависимостей используется простой
ввод без редактора; последний случай сопровождается подсказкой по установке.

10 октября 2026 подстановка `/1` + Tab проверена в настоящем терминальном
сеансе: вопрос дополнен перед отправкой, затем модель ответила «4».
HTTP занял 3,95 с, включая загрузку 2,05 с; ответ — 59 токенов,
скорость — 34,69 токена/с. `/prompts`, многострочная подстановка `/4`,
стрелки, переходы по словам и завершение проверены отдельно от генерации.
Это проверка редактора и одного ответа, а не общий показатель качества модели.

## Установка и хранение

Нужны macOS на Apple Silicon, Python 3.10+ и официальный
[Ollama для macOS](https://docs.ollama.com/macos). HTTP-клиент и простой ввод
используют стандартную библиотеку. Для редактора установите две небольшие
зависимости из `day-26` в папку проекта, без нового окружения:

```sh
python3 -m pip install --no-cache-dir --target ../.local-llm/cli-deps -r requirements.txt
```

Используются `prompt_toolkit==3.0.53` и `wcwidth==0.9.2`; установка уже выполнена
на текущем ноутбуке. Папка зависимостей занимает **8 779 934 байта** (около 8,8 МБ)
и исключена из Git вместе с `.local-llm/`. Файлы недели после добавления редактора
занимают около **3,30 ГБ**, в пределах бюджета 8 ГБ. Node.js для Day26 не нужен.

В этом проекте native runtime хранится в `.local-llm/runtime/ollama` корня,
а единственная копия весов — в `.local-llm/models/`. Вся папка `.local-llm/`
исключена из Git. Серверный скрипт также умеет находить установленную Ollama
через `OLLAMA_BIN`, `PATH` и `Ollama.app`.

Для воспроизводимой установки используем официальный native CLI **v0.40.2**,
без Homebrew, Docker и отдельного Python-окружения. Если runtime уже установлен,
повторно скачивать его не нужно. Перед загрузкой вручную проверьте свободное место
и бюджет; установочный архив временно добавляет ещё 167 473 220 байт сверх
распакованного runtime. Из корня проекта:

```sh
set -e
mkdir -p .local-llm/runtime
curl -fL --retry 2 -o .local-llm/ollama-v0.40.2-darwin.tgz \
  https://github.com/ollama/ollama/releases/download/v0.40.2/ollama-darwin.tgz
printf '%s  %s\n' \
  'e888b7637291ceb80b622c00ea067f62c86d9c50d419b3eb903032e4f1f8a4f6' \
  '.local-llm/ollama-v0.40.2-darwin.tgz' | shasum -a 256 -c -
tar -xzf .local-llm/ollama-v0.40.2-darwin.tgz -C .local-llm/runtime
rm .local-llm/ollama-v0.40.2-darwin.tgz
```

При несовпадении SHA256 распаковка не выполняется. После успешной распаковки
удаляется только скачанный установочный архив. Для запуска из корня проекта:

```sh
export OLLAMA_BIN="$PWD/.local-llm/runtime/ollama"
export OLLAMA_MODELS="$PWD/.local-llm/models"
"$OLLAMA_BIN" --version
cd day-26
./run-server.sh
```

Сервер работает в текущем терминале. `Ctrl+C` завершает этот процесс;
скрипт не создаёт автозапуск и не останавливает другие серверы. Если порт
11434 уже занят, Ollama выдаст ошибку запуска: сначала выясните, чей это процесс.

Во втором терминале **из корня проекта** загрузите только выбранный тег:

```sh
export OLLAMA_HOST=127.0.0.1:11434
export OLLAMA_MODELS="$PWD/.local-llm/models"
./.local-llm/runtime/ollama pull qwen3:4b-instruct-2507-q4_K_M
cd day-26
python3 cli.py check
```

Сеть нужна для установки и скачивания. Скрипт не скачивает модель автоматически.
Перед загрузкой бюджет проверяют вручную: новые файлы всей недели не должны
превышать **8 000 000 000 байт (8 ГБ)**. В него входят runtime, веса и дополнительные окружения/сборки.
`ollama pull` сам не проверяет этот бюджет. Размер слоёв официального манифеста
выбранной модели — **2 497 293 803 байта** (около 2,5 ГБ); к нему добавляется
распакованный runtime. Окончательный расход диска проверяется после загрузки;
полный расход RAM требует отдельного измерения. Источники: [тег модели](https://ollama.com/library/qwen3:4b-instruct-2507-q4_K_M),
[официальные releases](https://github.com/ollama/ollama/releases).

## Вспомогательные команды

Все команды ниже выполняются из `day-26`:

```sh
python3 cli.py check
python3 cli.py ask "Объясни локальную LLM простыми словами."
python3 cli.py demo --output data/demo.json
python3 cli.py unload
```

- `check` проверяет версию сервера, наличие выбранной модели, её параметры
  и capabilities через `/api/show`, загруженные модели через `/api/ps`.
  Эта команда не запускает генерацию.
- `ask` отправляет один запрос и выводит ответ, время HTTP, время загрузки,
  время генерации, число входных/выходных токенов и скорость, если метрики
  присутствуют в ответе сервера.
- `demo` сначала выгружает модель и проверяет `/api/ps`, затем последовательно
  отправляет три разных запроса: объяснение двумя предложениями; вычисление
  `1200 × 0,85 × 1,2 = 1224 ₽`; структурированная рекомендация для приложения.
  Первый запрос помечен `cold`, последующие — `warm`. Метка cold отражает
  выгрузку модели; кэш файлов ОС может оставаться прогретым. Другие клиенты
  не должны одновременно обращаться к серверу во время измерений.
- `unload` освобождает память модели и проверяет её отсутствие в `/api/ps`.
  Веса остаются на диске. Это не завершает сервер.

`--json` после `check`, `ask`, `demo` или `unload` выводит полный JSON:
запрос, ответ и исходные метрики. В `chat` этот флаг недоступен.
`--output` сохраняет тот же результат только внутри `day-26/data/`, исключённой
из Git. Произвольный `ask` по умолчанию ничего не сохраняет.

```sh
python3 cli.py check --json --output data/check.json
python3 cli.py ask "Что такое квантование?" --json
python3 cli.py demo --json --output data/demo.json
```

Исходный ресурсный кейс с числовыми фактами был одинаковым для всех трёх
кандидатов. Результаты сохранены локально в `data/`; ни одна модель не прошла
строгую проверку следования всем фактам этого кейса. Уточнение категорий RAM
и диска также не устранило все неточности.

Сложный запрос вспомогательной `demo` — другой кейс: рекомендация для CLI-RAG с локальным
индексом только для чтения, устареванием документов и вопросами вне корпуса.
Он проверяет структуру ответа, локальную цепочку retrieval и генерации,
ограничения и неизвестные данные. Смена кейса не доказывает исправление
ресурсных ошибок; итоговый кейс не сравнивался между моделями. Простой и
средний запрос остались прежними.

Наличие числа `1224` проверяется ограниченной эвристикой; она не доказывает
правильность вычислений. Объяснение и соблюдение условий сложного задания
оцениваются вручную. Усреднять cold и warm при оценке скорости нельзя.

## Прямой HTTP-запрос

При запущенном сервере можно обратиться к тому же API без нашего клиента:

```sh
curl --noproxy '*' http://127.0.0.1:11434/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen3:4b-instruct-2507-q4_K_M","messages":[{"role":"user","content":"Что такое локальная LLM?"}],"stream":false,"think":false,"options":{"temperature":0.7,"num_predict":512,"num_ctx":4096},"keep_alive":"1m"}'
```

## Настройки и ошибки

Серверный скрипт задаёт `OLLAMA_NO_CLOUD=1`, адрес `127.0.0.1:11434`,
одну загруженную модель, один параллельный запрос, контекст 4096 токенов
и выгрузку через минуту простоя. Это параметры нашего процесса; `check`
не доказывает настройки уже запущенного чужого сервера.

Каждый запрос задаёт `stream=false`, `think=false`, `temperature=0.7`,
`num_predict=512`, `num_ctx=4096`, `keep_alive=1m`.
`check` показывает capabilities, а фактическую поддержку non-thinking
проверяют успешным ответом на запрос. [Chat API](https://docs.ollama.com/api/chat),
[параметры runtime](https://docs.ollama.com/faq).

Клиент использует только loopback HTTP на порту 11434, игнорирует proxy
переменные и запрещает перенаправления. Альтернативный локальный адрес
задаётся перед командой: `python3 cli.py --url http://localhost:11434 check`.
Нет fallback в облако и автоматических повторов. Таймаут — 120 секунд.
Недоступный сервер, отсутствующая модель, HTTP-ошибка, таймаут, некорректный
JSON, незавершённый или пустой ответ отображаются по-русски. Коды выхода:
`0` — успех, `1` — ошибка, `130` — прерывание. После таймаута/прерывания сервер
может ещё завершать генерацию.

## Проверка задания и ресурсов

1. Выполнить `check`, открыть `chat`, отправить минимум три своих запроса
   разной сложности и вручную оценить ответы. `demo` остаётся вспомогательной
   воспроизводимой проверкой для разработки.
2. Во время генерации прочитать `http://127.0.0.1:11434/api/ps`: проверить
   имя модели, размер и размещение CPU/GPU; после `unload` проверить выгрузку.
3. После скачивания повторить `ask` при отключённом интернете или запрете
   внешних соединений процесса. `OLLAMA_NO_CLOUD=1` сам по себе не доказывает
   работу без сети.
4. Измерить размер `.local-llm/` командой `du -sh ../.local-llm` и состояние
   памяти в «Мониторинге системы»: memory pressure, swap и память процесса.
   Размер весов, RSS и `size_vram` по отдельности не равны расходу всей RAM.
5. Остановить наш сервер через `Ctrl+C`, запустить снова и повторить `check`
   и `ask`. Сохранить наблюдения локально в `data/`.

  Вся `.local-llm/` без повторного подсчёта symlink: **3 042 557 359 байт**,
  около **3,04 ГБ** / **2,83 ГиБ**. `du -sk`: 2 971 372 КиБ.
  Архив runtime и веса предыдущих кандидатов удалены. В лимите 8 ГБ остаётся
  около 4,96 ГБ для следующих дней; новые окружения пока не создавались.
- Первый запрос сразу после установки Instruct: **3,17 с**, включая загрузку
  **1,03 с**. В итоговой demo модель сначала выгружалась, но файловый кэш ОС
  уже был прогрет: **3,87 с** cold, загрузка **0,78 с**, 101 выходной токен.
- Средний запрос: **8,89 с** warm, 298 токенов; вычисления
  `1200 − 180 = 1020`, `1020 + 204 = 1224 ₽` правильны.
- Сложный запрос: **6,63 с** warm, 199 токенов; 76 слов, три требуемых раздела,
  локальная цепочка, существующие модель/индекс, отказ при отсутствии контекста
  или устаревшем индексе, явно неизвестные параметры. Условия выполнены.
- Скорость итоговой demo: **34,38–34,87 токена/с**. Все ответы непустые,
  `done_reason=stop`, без thinking-блоков. Первый ответ содержит два предложения.
  Это небольшая демонстрация, а не общий benchmark качества.
- Во время генерации `/api/ps`: выбранный тег, контекст 4096,
  `size=size_vram=3 175 339 786 байт`; native `ollama ps`: **100% GPU**.
  Пик RSS runner в итоговом прогоне **3,11 ГиБ**, в первом **3,13 ГиБ**.
  Эти показатели общей памяти Apple Silicon нельзя складывать между собой
  или выдавать за полный расход RAM всей системы.
- Системный `kern.memorystatus_vm_pressure_level` оставался **1 (normal)**.
  Swap до/после итогового прогона **2772,75 МиБ**, роста в этом прогоне нет;
  swap уже использовался другими нагрузками и предыдущим тестом 9B.
  Показатель `memory_pressure -Q` free percentage менялся в пределах 49–63%;
  это отдельный показатель, а не процент RAM, занятый моделью.
- Все три итоговых CLI-запроса выполнены при запрете внешней сети для
  сервера и его runner. В том же профиле внешний HTTPS-запрос завершился
  ошибкой соединения (exit 7), а loopback API работал. Wi-Fi ноутбука не отключали.
- После `unload` список `/api/ps` пуст. Обычный сервер повторно запущен,
  CLI `ask` снова получил ответ; наш процесс остановлен `Ctrl+C`, порт освобождён.
  После первоначальной проверки сервер оставили остановленным для экономии памяти.
  При последующей проверке интерактивного чата использовали уже работающий
  сервер пользователя и оставили его работать.

Обычный `ollama pull` первоначально завершился TLS handshake timeout.
Для этого запуска слои скачаны через `curl` из официального OCI registry Ollama;
каждый размер и SHA256 сверены с официальным manifest, включая config.
Это те же артефакты выбранного тега. Manifest и квитанция установки сохранены
локально в `data/`; команда `pull` выше остаётся стандартным способом установки.

### Почему изменился выбор модели

Исходный ресурсный prompt был одинаковым для всех трёх кандидатов:
24 ГБ RAM, бюджет новых файлов 6 ГБ, около 3,3 ГБ файлов весов. Это учебные
условия вопроса, а не описание итоговой установки. Сравнение показало:

- Qwen3.5 4B: около 28 токенов/с, пик RSS 3,75 ГиБ; три проверки сложного
  вопроса дали смешение диска и RAM либо придуманные параметры.
- Qwen3.5 9B: веса 6,55 ГБ, около 16 токенов/с, пик RSS 6,58 ГиБ.
  Исходный сложный ответ снова смешал диск и RAM. При загрузке pressure level
  прошёл 1 → 4 (critical) → 2 (warning), после выгрузки вернулся к 1;
  swap вырос с 1450,25 до 2876,75 МиБ. Для текущей нагрузки ноутбука кандидат
  отклонён; увеличение дискового бюджета не устранило ограничение RAM.
- Qwen3 Instruct 4B: около 35 токенов/с, ниже расход памяти и нормальный pressure.
  Исходный ресурсный вопрос тоже не прошёл строгое следование фактам.
  Явное разделение категорий устранило основное смешение величин, но оставило
  неточности (например, «общая RAM неизвестна» вместо известных 24 ГБ).

Итоговая demo использует **другой сложный кейс о поведении приложения**,
описанный выше. Он дважды дал ответы с соблюдением условий. Это не доказательство
исправления прежней ошибки и не сравнение нового кейса между моделями.
Повторный `ask` после перезапуска также показал ошибку в определении: модель
неверно описала локальность обучения вместо локальности исполнения.
Модель можно использовать для учебного чата с ручной проверкой, но сложные числовые ограничения пока
ненадёжны: такие расчёты в приложении следует проверять кодом. Качество RAG на момент этого раннего прогона ещё не оценивалось;
последующие результаты описаны в README Day28. Дополнительные веса
автоматически не скачиваются.

Исходные запросы, ответы, метрики, измерения памяти, offline-профиль и результаты
предыдущих кандидатов находятся только в `data/`, исключённой из Git.

## Воспроизводимая проверка без внешней сети на macOS

После загрузки остановите свой обычный сервер. Из `day-26` создайте локальный
профиль и запустите Ollama через него:

```sh
mkdir -p data
cat > data/offline.sb <<'PROFILE'
(version 1)
(allow default)
(deny network*)
(allow network-outbound (remote ip "localhost:*"))
(allow network-inbound (local ip "localhost:*"))
PROFILE
/usr/bin/sandbox-exec -f data/offline.sb ./run-server.sh
```

Во втором терминале из `day-26`:

```sh
/usr/bin/sandbox-exec -f data/offline.sb curl --noproxy '*' --max-time 5 https://1.1.1.1
python3 cli.py check
python3 cli.py demo --output data/offline-demo.json
python3 cli.py unload
```

Внешнее соединение должно завершиться ошибкой, а local API и генерация —
работать. Ограничения наследует дочерний runner Ollama. Профиль блокирует сеть
runtime, не отключая Wi-Fi всего ноутбука; это проверка автономности процесса.
`sandbox-exec` — системный инструмент этой macOS; доступность на других версиях
не гарантируется. Завершите сервер `Ctrl+C` и запустите обычный `./run-server.sh`.

## Автоматические тесты

```sh
python3 -m unittest discover -s tests -v
```

Все **47 тестов** проходят; прежние 31 также проходят отдельно. Тесты используют поддельный HTTP-транспорт: проверяют параметры запросов,
метрики, выгрузку, последовательность demo, ограничения адреса,
отказ при redirect, HTTP/timeout/JSON-ошибки, отсутствующую модель, пустой
ответ и CLI-коды выхода. Отдельные сценарии проверяют историю чата,
целостность пар, UTF-8 бюджет, отсутствие сохранения, команды и прерывания.
Реальных запросов и загрузок моделей они не делают.
Тесты редактора подают реальные последовательности клавиш через
`create_pipe_input`: проверяют подстановку без отправки, правку текста,
переходы по словам/строкам, вставку нескольких строк, EOF/Ctrl+C,
отсутствие сохранения ввода и выбор TTY/простого ввода.
Production build для Python CLI не требуется.

Тесты чата дополнительно проверяют передачу предыдущих вопросов и ответов,
очистку истории, удаление целых пар при достижении лимитов, отказ длинному
вопросу до HTTP, сохранение истории после ошибки, EOF/прерывание и отсутствие
записи разговора на диск.
