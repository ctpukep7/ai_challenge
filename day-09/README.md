# Day 09 — Управление контекстом: сжатие истории

Учебное приложение сравнивает два синхронизированных диалога на одном и том же вопросе:

- **Полный контекст** каждый раз отправляет в LLM всю переписку.
- **Сжатый контекст** оставляет последние `N` сообщений как есть, а более раннюю часть заменяет rolling-summary, созданным той же моделью.

Обе ветки, сообщения, summaries и фактические метрики API хранятся в SQLite. После перезапуска эксперименты остаются доступны.

## Как работает сжатие

Параметры сжатия задаются в «Настройках». Например, при `сжимать каждые 10` и `оставлять последних 6` приложение ждёт 16 несжатых сообщений: 10 для нового фрагмента summary и 6 последних сообщений. Затем агент:

1. отправляет первые 10 сообщений вместе с предыдущим summary в отдельный LLM-вызов и получает структурированную Markdown-сводку;
2. сохраняет новый summary отдельно в SQLite;
3. помечает эти 10 сообщений архивными;
4. в следующем запросе отправляет только system-настройки, summary, последние 6 сообщений и новый вопрос.

Архив остаётся доступен в SQLite для проверки, но не расходует контекст LLM. Если LLM не смогла создать summary, архивирование не происходит: сжатая ветка продолжает передавать полную историю и не теряет данные.

## Запуск одной командой

Нужны Python 3.11+ и Node.js 20+.

```bash
cd day-09
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
npm install
npm --prefix frontend install
cp .env.example .env
# укажите DEEPSEEK_API_KEY или OPENROUTER_API_KEY
npm run dev
```

Откройте [http://127.0.0.1:5175](http://127.0.0.1:5175). Одна команда запускает FastAPI на `5008` и Vue/Vite на `5175`; ключи остаются только на Python-бэкенде.

Проверки:

```bash
npm test
npm run build
```

## Сценарии сравнения для видео

Под полем ввода нажимайте `▦ Шаг`, затем `Сравнить ответы →`. Вопросы только подставляются в поле — отправку вы контролируете сами.

**Реестр лаборатории** содержит девятнадцать насыщенных партиями образцов ходов и финальную сверку восьми ранних и поздних записей. В первом шаге задаётся обращение «Доктор Д», а каждый последующий шаг добавляет дополнительный протокол из 18 записей: код, шкаф, массу, температуру, цвет пломбы и статус. Это проверяет, не потерялись ли точные детали среди большого объёма данных.

Приложение использует `сжимать каждые 10` и `оставлять последние 6`. Каждый шаг сохраняет два сообщения — вопрос и ответ: поэтому summary создаётся после 8-го, 13-го и 18-го шага. Финальная проверка — 20-й шаг. Для summary не задаётся `max_tokens`: он не обрезается искусственным лимитом и может сам выбрать необходимую длину.

Для сравнения:

1. Проведите сценарий до финального контрольного вопроса в новом эксперименте.
2. Сопоставьте два финальных ответа по фактам.
3. Посмотрите «Экономию входа», суммарные токены и стоимость. В сжатом режиме цена summary показывается отдельно и уже включена в итог.
4. Откройте `ⓘ JSON`: в полном режиме будет вся история, в сжатом — summary и последние `N` сообщений.
5. Нажмите «Все summary» в карточке сжатого контекста: откроется вся цепочка созданных сводок, а не только актуальная.

## Что измеряется

После каждого ответа используются только фактические поля `usage`, возвращённые API: входные, выходные и общие токены, время, причина завершения и стоимость при её наличии. Отдельно учитываются LLM-вызовы для summary, поэтому сжатие сравнивается честно: видно как экономию последующих запросов, так и начальную цену компрессии.

`data/context.sqlite3` и `.env` игнорируются Git — реальная переписка и API-ключи в репозиторий не попадают.
