# День 30. Локальная LLM как приватный сервис

Домашний Mac обслуживает русский веб-чат и HTTP API через HTTPS. Генерация выполняется установленной `qwen3:4b-instruct-2507-q4_K_M` в нативном Ollama. Сервис Day30 самостоятельный: не зависит от текущих профилей и экспериментов Day29.

## Соответствие заданию Day30

- **Домашний сервер:** Mac запускает отдельный HTTPS-сервис с одним worker;
  Ollama остаётся на loopback. Реализованы HTTP API и русский веб-чат.
- **Приватность и ограничения:** API защищён токеном; одна генерация без
  очереди, 6 принятых запросов в минуту, 6000 UTF-8 байт входного контекста
  и 32 КиБ тела HTTP. Байтный лимит не является точным подсчётом токенов.
- **Сетевой доступ:** сохранены успешные HTTPS-проверки API с самого Mac.
  Пользователь подтвердил открытие экрана входа с другого устройства.
  Авторизованный запрос к модели с этого устройства ещё не подтверждён.
- **Стабильность при нескольких запросах:** тесты с поддельным транспортом
  проверяют занятость, освобождение слота, ошибки и rate limit. Несколько
  последовательных живых генераций через Day30 ещё не подтверждены.
- **Результат:** сервис реализован; полную приёмку сетевого чата и живой
  последовательности запросов пока нельзя объявить завершённой.

Перепроверка 12 октября 2026: прошли 29 backend/CLI и 16 frontend тестов,
production build. Новые сетевые генерации, настройка сертификата и запуск
сервиса при этой перепроверке не выполнялись.

## Подготовка

Используются runtime и веса Day26, Python-окружение Day21 и frontend-зависимости Day27. Новые модели, Docker, окружения и зависимости не скачиваются. Для переноса на другой компьютер эти зависимости необходимо установить отдельно.

Из `day-30`:

```bash
npm run build
npm run setup -- --host 192.168.0.171
npm start -- --host 192.168.0.171
```

Ollama должен уже работать на `127.0.0.1:11434`; сервис не останавливает его и не меняет его конфигурацию. Если Ollama отсутствует, запустите `../day-26/run-server.sh` отдельно.

Сертификат и случайный токен создаются локально в игнорируемом `data/`, существующий токен не заменяется. Токен не помещается в URL и не сохраняется браузером. Сертификат самоподписанный: клиентскому устройству нужно доверять ему, либо для CLI указать `--cacert data/tls-cert.pem`. Изменение LAN-адреса требует обновления SAN сертификата. Не открывайте порт Ollama или роутера в интернет.

## Общение

Откройте `https://192.168.0.171:5029` и введите токен из локального `data/access-token`. Не публикуйте токен. Enter отправляет, Shift+Enter добавляет строку. Беседа хранится только в памяти вкладки; перезагрузка, выход и новый чат очищают её. В модель передаются последние четыре полные пары сообщений. Сервер не сохраняет сообщения в базу или журнал.

## Ограничения

- 6 принятых запросов генерации в минуту на общий токен; HTTP429 и Retry-After.
- Одна генерация, без очереди; второй запрос получает HTTP409.
- SYSTEM, история и новый вопрос вместе до6000байт UTF-8; превышение HTTP413 без генерации. Это лимит текста, а не точная токенизация.
- Контекст модели4096токенов, выход1024, temperature0.7, thinking выключен; по достижении лимита ответ может быть неполным.
- Максимум32КиБ тела HTTP, в том числе без Content-Length.
- HTTPX ограничивает отдельные сетевые ожидания120с; это не общий deadline
  всего запроса. Браузер прекращает ожидание через125с, повторов нет. См.
  [документацию HTTPX](https://www.python-httpx.org/advanced/timeouts/).
- Лимиты находятся в RAM одного worker и сбрасываются при перезапуске. Это учебный сервис для небольшой домашней сети.

Ollama остаётся на loopback. На сетевом API обязательна авторизация; чат загружается без токена, но не раскрывает состояние модели и не генерирует ответы до входа. HTTPS шифрует передачу токена и текстов. Сервис работает, пока Mac включён, не спит и процесс запущен. Автозапуск и изменение системных настроек не добавляются. Ctrl+C останавливает только Day30.

## HTTP API

`GET /api/health` проверяет наличие модели и версию Ollama без загрузки весов. `GET /api/limits` возвращает параметры и ограничения. `POST /api/chat` принимает `{"prompt":"Привет","history":[]}`; каждая пара истории имеет `user` и `assistant`. Везде требуется `Authorization: Bearer <токен>`.

Ответ содержит `answer`, `model`, `truncated`, `metrics`: полное время, загрузка, генерация, токены входа/выхода/всего и скорость генерации. Если Ollama не сообщила метрику, значение `null`, в чате «Нет данных». Ошибки имеют форму `{"error":{"code":"...","message":"..."}}`. Неизвестный API возвращает404, а не HTML. Нет универсального прокси к Ollama, облачного маршрута и возможности загрузить модель через API.

CLI-клиент не требует дополнительных зависимостей:

```bash
python3 scripts/client.py health
python3 scripts/client.py ask "Объясни локальную LLM двумя предложениями."
```

Для другого компьютера скопируйте `scripts/client.py`, публичный сертификат `data/tls-cert.pem` и файл токена на доверенное устройство. Приватный TLS-ключ остаётся на сервере. Пути задаются явно:

```bash
python3 client.py --url https://192.168.0.171:5029 \
  --cert tls-cert.pem --token-file access-token health
```

Клиент использует проверку сертификата, не следует перенаправлениям и не использует proxy из окружения. Токен читается из файла, а не из аргумента командной строки. Для браузера вручную установите доверие локальному сертификату; встроенный браузер Codex пока его отклоняет.

## Проверка · 12 октября 2026

```bash
npm test
npm run build
```

29 backend/CLI-тестов и 16 frontend-тестов прошли; production build успешен. Поддельный транспорт проверяет авторизацию, частоту запросов, предел контекста и HTTP-тела, chunked-запросы и неверный Content-Length, занятость и освобождение слота, таймаут, некорректные JSON/Unicode и ответы модели, отсутствие повторов и утечек в ошибках.

Настоящий HTTPS на сетевом адресе Mac проверен с доверенным сертификатом: страница, limits и health возвращают 200, отсутствие токена — 401, неизвестный API — 404, превышение контекста — 413, частые ошибочные входы — 429 с Retry-After. Health видит Ollama 0.40.2 и установленную Q4. CLI health также работает. Эти автоматические запросы выполнялись с самого Mac.

После просьбы подключиться с телефона или другого компьютера пользователь сообщил: «Зашел, пишет нужен токен». Доступ до экрана входа на клиентском устройстве подтверждён. Авторизованный обмен на этом устройстве ещё не подтверждён.

Встроенный браузер отклонил самоподписанный сертификат; предупреждение не обходилось. Интерфейс проверен на отдельном временном loopback-стенде с тем же кодом, тестовым токеном и поддельным ответом: вход, лимиты, отправка, блокировка во время ожидания, семь метрик, новый чат и выход. Реальная модель на стенде не вызывалась. При ширине 1600 и 487 CSS-пикселей горизонтальной прокрутки нет. Запрошенные 390×844 браузер применил как 487 CSS-пикселей; точные 390 не подтверждены. Стенд остановлен.

Остановка и повторный запуск Day30 прошли. Повторная настройка сохранила исходные токен и сертификат. Второй запуск на занятом порту завершился с понятной ошибкой и сохранил работающий сервис. Соседние приложения и Ollama не останавливались; 61 исходный файл Day26–28 совпадает по хешам. На момент той проверки Day29 изменялся другим чатом; его тогда не редактировали.

Day30 занимает около 0,4 МБ выделенного диска, включая сборку и отчёты; зависимости переиспользуются. Общий расход недели около 7,60 ГБ из 8 ГБ во время испытаний Q8 другим чатом. Day30 не скачивает модели. Токен, TLS-ключ, отчёты и скриншоты исключены из Git. Папка data имеет права 0700, токен и ключ — 0600. Содержимое секретов не выводилось в отчёты.

Несколько настоящих генераций Day30 пока не проверены. Во время первоначальной проверки модель была занята экспериментами Day29; завершение Day29 само по себе не подтверждает стабильность Day30. Для окончательной приёмки нужны эти ответы и авторизованный чат с клиентского устройства. Поддельные ответы UI не являются результатом живой LLM.


## Мобильная версия

Применены рекомендации [responsive-design](https://skills.sh/wshobson/agents/responsive-design) и локального build-responsive-front-end-designs. Текст сообщений и поля ввода — 16 px, кнопки — минимум 44 px высотой. На телефоне метрики размещаются в две колонки, отправка занимает ширину формы. Лимиты раскрываются в блоке «Ограничения сервиса». Учтены безопасные отступы экранов с вырезами; масштабирование браузера разрешено.

Повторная проверка в браузере подтвердила фактические ширины 320, 390, 430, 767 и 1280 CSS-пикселей: пустой чат и длинный ответ без горизонтальной прокрутки. На 320 проверены раскрытые лимиты; на 390 — ошибка превышения контекста с сохранением черновика. Использован временный стенд с поддельным транспортом, без вызова LLM. Он остановлен. Проверка на физическом телефоне с экранной клавиатурой остаётся отдельной проверкой. 16 frontend-тестов и production build прошли. Скриншоты и измерения находятся в игнорируемой data/.

По просьбе пользователя подготовленные вопросы удалены: кнопок и команд /номер + Tab больше нет. Tab переводит фокус, введённые /1–/4 остаются обычным текстом. Проверено в браузере на ширине 390 CSS-пикселей без горизонтальной прокрутки; 16 frontend-тестов и сборка прошли.
