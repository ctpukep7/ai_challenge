# Day 10 — управление контекстом без summary

Приложение сравнивает три независимые стратегии одного агента. История каждого эксперимента хранится в SQLite и восстанавливается после перезапуска.

| Стратегия | Что отправляется модели | Зачем нужна |
| --- | --- | --- |
| Sliding Window | Последние **N** сохранённых сообщений + текущий вопрос | Минимальный и предсказуемый расход контекста |
| Sticky Facts | Key-Value facts + последние **N** сохранённых сообщений + текущий вопрос | Сохраняет цель, ограничения и решения за пределами окна |
| Branching | Полная линия текущей ветки | Позволяет продолжить один checkpoint двумя независимыми путями |

`N` относится к уже сохранённой истории; текущий user-message добавляется в
запрос отдельно. Facts — не summary: это JSON-объект с ключами `goal`,
`constraints`, `preferences`, `decisions`, `agreements`, `open_questions`.
Для каждого user-message приложение делает отдельный вызов обновления facts и
учитывает его токены и стоимость в метриках Sticky Facts. Если этот вызов или
его JSON-ответ не удался, основной ответ использует предыдущие facts и UI
показывает предупреждение.

## Архитектура и данные

- FastAPI отдаёт API экспериментов, отправки prompt, создания checkpoint и
  выбора активной ветки.
- Vue/Vite показывает три стратегии рядом, метрики, JSON фактических запросов
  без API-ключа и историю facts.
- SQLite хранит `experiments`, `threads`, `messages`, `facts_snapshots`,
  `checkpoints` и `turns`. История восстанавливается после перезапуска.
- Для Branching дочерние A и B наследуют сообщения корня только до checkpoint;
  новые сообщения одной ветки не входят в контекст другой.

## Запуск одной командой

Нужны Python 3.11+ и Node.js 20+.

~~~bash
cd day-10
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
npm install
npm --prefix frontend install
cp .env.example .env
# укажите DEEPSEEK_API_KEY или OPENROUTER_API_KEY
npm run dev
~~~

Откройте [http://127.0.0.1:5176](http://127.0.0.1:5176). FastAPI работает на 5009, Vue/Vite — на 5176. Ключи остаются только на Python-бэкенде.

Проверки:

~~~bash
npm test
npm run build
~~~

## Сценарий для видео

1. Создайте новый эксперимент. Оставьте одинаковые настройки: один провайдер,
   одну модель, `temperature = 0`, окно `N = 6` и режим «Сравнить все
   стратегии».
2. Нажимайте `▦ Следующий шаг`, затем `Отправить →`: первые семь prompts
   собирают факты ТЗ.
3. Восьмой, контрольный prompt просит сформировать ТЗ и назвать цель, роли,
   срок, бюджет, функции, SSO, запреты на данные, платформу и исключённые
   функции. Он проверяет, что каждая стратегия сохранила ранние условия после
   выхода части сообщений из окна.
4. Сравните три ответа и метрики: входные токены, выходные токены, время и
   итоговую стоимость. Sticky Facts дополнительно учитывает расходы на
   обновление памяти. Откройте `ⓘ JSON` и `Facts`, чтобы показать реальные
   запросы без API-ключа.
5. После контрольного шага нажмите «Создать checkpoint». Появятся ветки A и B.
6. Переключитесь на A и отправьте её три готовых шага, затем повторите три
   шага для B. Каждая ветка получает общее ТЗ до checkpoint, но не видит новые
   решения соседней ветки.

## Как сравнить результат

| Признак | Что проверить |
| --- | --- |
| Качество | Следует ли ответ условиям текущего вопроса |
| Стабильность | Помнит ли агент цель, сроки, бюджет, SSO и договорённости |
| Токены и стоимость | Насколько меняются входные токены и общая стоимость стратегий |
| Удобство | Хватает ли окна, facts или отдельных веток для конкретного сценария |

Branching не предназначен для разбиения любого линейного диалога. Он полезен в
точке выбора взаимоисключающих вариантов — например, двух версий ТЗ. Ветки не
нужно сливать обратно: пользователь продолжает выбранную траекторию.

## Настройки и жизненный цикл стратегий Day 10

В Day 10 `POST /api/ask` принимает `experiment_id`, `prompt`, `controls`, `window_size` и `target`. По умолчанию target — `all`, окно — 6 уже сохранённых сообщений, DeepSeek — `deepseek-v4-flash`, temperature 0, thinking disabled, без формата, max_tokens и stop sequences. Альтернативные target: `sliding`, `facts`, `branching`; для OpenRouter исходная модель — `openrouter/free`. Окно допускает только чётные значения 2–100, temperature — 0–2, max_tokens — 1–100000, stop-маркеров — до 16. При DeepSeek thinking enabled temperature не передаётся.

В режиме `all` Day 10 запускает стратегии параллельно. Sliding Window и Branching делают по одному вызову ответа; Sticky Facts сначала обновляет память отдельным вызовом, затем получает ответ. Успех одной стратегии сохраняется независимо от ошибки другой, поэтому после частичного сбоя истории могут различаться. В режиме отдельной стратегии пополняется только её история. Полные тексты Sliding Window и Sticky Facts остаются в SQLite даже после выхода из окна; ограничивается передача в модель, а не хранение.

Память Sticky Facts в Day 10 содержит шесть известных ключей с массивами строк. При разборе JSON отсутствующие ключи становятся пустыми массивами, строка превращается в массив из одной строки, лишние ключи игнорируются, пустые строки и дубликаты убираются. Обновление получает предыдущий JSON и только новое user-сообщение: ответы ассистента не извлекаются в facts отдельным этапом. Для обновления используются temperature 0 и thinking disabled, без max_tokens и stop sequences. При невалидном JSON или сбое вызова основной ответ продолжается с прежними facts и предупреждением; snapshot сохраняется только после успешных обновления и основного ответа.

Checkpoint Day 10 создаётся после последнего успешного assistant-сообщения корневой Branching-ветки. Один эксперимент поддерживает один checkpoint и две дочерние ветки A/B; повторное создание возвращает существующий checkpoint. Сразу активируется A. После checkpoint API запрещает target `all`, а продолжение выбранной ветки отправляется с target `branching`. A и B наследуют общий корень до сохранённой границы и свои дальнейшие сообщения. Контекст Branching передаётся целиком по этой линии, поэтому он растёт и может достичь лимита модели. Автоматического слияния, рекурсивных новых checkpoint или сжатия нет.

## Что означают метрики Day 10

Метрики Day 10 складывают сохранённые успешные ответы и facts snapshots. Расход обновления facts включён в общий итог Sticky Facts, но сбой facts, невалидный JSON или успешное обновление перед ошибкой основного ответа не сохраняют отдельную запись расхода. Поэтому такая сумма может быть ниже фактического списания провайдера. Стоимость берётся из API cost либо оценивается встроенной таблицей; отсутствующая цена обозначается как неизвестная.

Для Branching общий итог Day 10 учитывает все реальные ответы корня, A и B по одному разу; карточка последнего ответа соответствует активной линии. Сумму всех веток нельзя считать стоимостью исключительно выбранного пути. Facts и summaries различаются форматом и входом, но оба зависят от LLM: правильный JSON не гарантирует, что все ранние ограничения сохранены верно. Проверять это нужно по ответу и истории facts.
