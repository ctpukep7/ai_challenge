# День 27. Веб-чат с локальной LLM

Собственные вопросы и уточнения в русском веб-чате: Vue отправляет их в FastAPI,
а FastAPI обращается к Ollama на этом ноутбуке. Используется уже установленная
модель `qwen3:4b-instruct-2507-q4_K_M` из Day26. Облачных моделей и новых весов нет.

## Соответствие заданию Day27

- **Приложение:** русский веб-чат с Vue и FastAPI.
- **Запрос и ответ:** браузер вызывает `/api/chat`, backend обращается к
  локальному Ollama и возвращает настоящий текст ответа для отображения.
- **Без облачных моделей:** нет облачного клиента, ключа или fallback.
  Runtime и веса переиспользуются из Day26.
- **Результат:** интеграция подтверждена четырьмя сохранёнными живыми HTTP-
  обменами и браузерными проверками. Известные ошибки ответов описаны ниже.

Перепроверка 12 октября 2026: прошли 40 backend и 17 frontend тестов,
production build. Ниже сохраняется история прежних проверок; первоначальные
11 frontend тестов не являются актуальным итоговым количеством.

## Установка

Сначала завершите установку [Day26](../day-26/README.md). Затем из корня проекта:

```bash
cd day-27
python3 -m venv .venv
PIP_NO_CACHE_DIR=1 .venv/bin/python -m pip install -r requirements.lock.txt
npm --prefix frontend ci --cache ../.local-llm/npm-cache --no-audit --no-fund
```

Окружение небольшое: FastAPI, uvicorn, HTTPX и pytest, без embedding-моделей
и ML-библиотек. Runtime и веса переиспользуются; общий рабочий бюджет недели —
8 ГБ. Перед дополнительными загрузками учитывайте также `.venv`, `node_modules`,
кэш npm и сборку. Новые веса автоматически не скачиваются.

## Запуск и собственное общение

```bash
npm run dev
```

Откройте <http://127.0.0.1:5193>. Введите свой вопрос и нажмите Enter;
Shift+Enter добавляет новую строку. Пока модель отвечает, видны индикатор и время
ожидания. Под ответом отображаются время, выходные токены и скорость генерации.
«Новый чат» очищает беседу и её контекст.

API слушает `127.0.0.1:5026`, Ollama — `127.0.0.1:11434`. Launcher переиспользует
работающий Ollama и оставляет его после остановки чата. Если Ollama не запущен,
launcher явно запускает сервер Day26 собственным процессом. Ctrl+C останавливает
только созданные им процессы; автозапуск macOS не добавляется.

Готовая сборка также работает без Vite:

```bash
npm run build
npm run serve
```

В этом режиме чат открывается на <http://127.0.0.1:5026>.

## Подготовленные вопросы

Над полем ввода доступны четыре кнопки с вопросами из Day03/05,
как в консоли Day26:

- `/1` — свечи.
- `/2` — переправа животных.
- `/3` — два предложения без буквы «а».
- `/4` — слова стихотворения в алфавитном порядке.

Нажатие кнопки заменяет черновик полным текстом и возвращает фокус в поле.
Можно также ввести `/1`–`/4` и нажать **Tab**. Вопрос можно отредактировать;
подстановка сама не отправляет его модели и не меняет историю беседы.
**Enter на полном тексте** или кнопка отправки отправляют вопрос.
Enter на самом обозначении тоже только подставляет текст, как в Day26.

Код должен занимать всё поле: внутри обычного вопроса он не заменяется.
Обычный Tab и Shift+Tab сохраняют переход фокуса; Shift+Enter — новую строку.
Во время генерации кнопки подстановки недоступны. Дополнительные зависимости
и новые веса для этой возможности не нужны.

## Память беседы и ограничения

Беседа хранится только в оперативной памяти страницы. Перезагрузка её очищает;
сервер не сохраняет тексты в базу или файлы. В модель передаются максимум четыре
предыдущие пары вопрос–ответ. Общий текст контекста и нового вопроса ограничен
3000 байт UTF-8; старые пары при необходимости удаляются целиком, о чём чат
сообщает. Новый вопрос не обрезается. Лимит байт — консервативная оценка,
а не точный подсчёт токенов.

Фиксированы `temperature=0.7`, `num_predict=1024`, `num_ctx=4096`, `think=false`,
`keep_alive=1m`. Выполняется одна генерация; другая вкладка получит сообщение,
что модель занята. Backend ждёт максимум 120 секунд, браузер — 125 секунд.
Автоматических повторов нет. После ошибки история не меняется; вопрос можно
отправить самостоятельно. Локальная компактная модель может ошибаться:
факты и расчёты требуют проверки. Ответ при достижении лимита токенов может
быть неполным; интерфейс сообщает об этом.

После установки запросы проходят только по loopback. Для чата не нужны
API-ключи, внешний CDN или доступ к облачной модели. Это локальное приложение;
сетевое развёртывание с авторизацией относится к Day30.

## HTTP API

`GET /api/health` проверяет версию Ollama и наличие модели, не загружая веса.
`POST /api/chat` принимает собственный вопрос и историю полными парами:

```bash
curl http://127.0.0.1:5026/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"prompt":"Объясни локальную LLM двумя предложениями.","history":[]}'
```

Ответ содержит `answer`, `model`, `dropped_pairs`, `truncated` и `metrics`
(общее время, загрузка, генерация, входные/выходные токены, токены в секунду).
Ошибки имеют форму `{"error":{"code":"...","message":"..."}}` с русским
сообщением: 409 занято, 413 длинный вопрос, 422 неверный запрос, 503 сервер
или модель недоступны, 504 таймаут, 502 ошибка ответа модели.

## Проверка

```bash
npm test
npm run build
```

Backend-тесты используют поддельный HTTP-транспорт. Они проверяют контекст,
параметры, метрики, ошибки, таймаут и блокировку параллельной генерации без
загрузки модели. Frontend-тесты проверяют состояние беседы и ограничение истории.

Проверено на Apple M4 / 24 ГБ / macOS 15.7.7, Python 3.14.2, Node 26.8.1:

- 40 backend-тестов и 11 frontend-тестов прошли; production build успешен.
- Четыре настоящих обмена через HTTP: название проекта, уточнение с контекстом,
  расчёт, структурированная рекомендация. Все ответы непустые. На арифметике
  модель сначала написала неверные 1056 ₽, затем сама исправилась на 1224 ₽;
  такой ответ нельзя считать безусловно правильным. В рекомендации было
  три пункта и строка «Неизвестно», число пользователей не выдумано.
- Первый ответ: 2,54 с всего, из них 2,06 с загрузка весов. Следующее короткое
  уточнение: 0,26 с, загрузка 0,005 с. Более длинные ответы: 33,3 и 32,6 ток/с.
  Это отдельные наблюдения, а не гарантированная скорость всех вопросов.
- Во время генерации health ответил за 0,008 с; параллельная генерация получила 409.
- Браузер: 1440×900 и 390×844 CSS-пикселей, своя беседа и уточнение «Маяк»,
  индикатор ожидания и запрет повторной отправки, новый чат, сброс при перезагрузке,
  Shift+Enter, длинная непрерывная строка без горизонтальной прокрутки.
  Занятость сохранила вопрос и прежнюю историю; 3002 байта нельзя отправить.
- Готовая сборка чата действительно получил ответ без Vite; ошибок в консоли нет.
  Статические JS/CSS локальные, API-клиент обращается только к 127.0.0.1,
  облачных маршрутов и CDN в приложении нет. Отдельное отключение интернета
  для Day27 не проводилось; автономность самой модели проверена в Day26.
- Остановка нашего скрипта запуска завершила API/Vite. Повторный запуск работает;
  запуск на занятом порту 5026 завершается ошибкой и сохраняет работающий чат.
  Пользовательский Ollama PID 94009 оставался запущен. Ветку автостарта
  при отсутствующем Ollama в этой проверке не запускали.
- Исходники Day26 совпадают с хешами до реализации; дни01–25 не изменены.

Новые файлы Day27: около 91,6 МБ (окружение, зависимости, сборка и проверки).
Общий размер файлов недели с единственными весами и runtime, Day26 и npm-кэшем:
**3,29 ГБ из 8 ГБ**. В том числе npm-кэш 154,5 МБ, его размер тоже учтён.
Файловые размеры подсчитаны без повторного учёта символических ссылок.
API в production в момент проверки занимал 48048 КиБ RSS (около 46,9 МиБ).
Это расход процесса API, не модели и не всей системы. Система показала 41%
свободной памяти и 2628,75 МБ занятого swap; значения относятся ко всем
приложениям ноутбука и не доказывают изменение swap из-за Day27.

Синтетические записи проверок и снимки лежат в игнорируемом `data/`.
Обычные пользовательские беседы приложение туда не пишет. Компактная модель
также дала неточное определение локальной LLM в браузерной проверке: локальный
запуск не означает обучение исключительно на локальных данных.
