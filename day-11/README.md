# Day 11 — слои памяти stateful-агента

Локальная учебная лаборатория показывает, как stateless-вызов LLM превращается
в агента с разными областями памяти. Модель не обучается на сообщениях и не
записывает память самостоятельно: каждое изменение запускает пользователь.

| Слой | Где хранится | Как меняется | Что получает модель |
| --- | --- | --- | --- |
| Константы | Python-код | Не меняются через UI или модель | Первый system-блок |
| Краткосрочная | `sessions`, `messages`, ветки и сжатие | Успешный ход, новая/выбранная/сброшенная сессия или ветка | История активной сессии в выбранном режиме |
| Рабочая | `tasks` | Добавление текста в одно поле или выбор темы | Данные текущей задачи; готовые вопросы сюда не записываются |
| Долговременная | `long_term_entries` | Добавление или удаление пользователем | Произвольные записи во всех сессиях и задачах |

Долговременная память намеренно не делится на категории: пользователь может
сохранить любой полезный текст длиной до 500 символов. Формальный профиль,
настройки стиля и автоматическое извлечение памяти не входят в День 11.

`memory_events` хранит безопасный аудит: слой, действие, автор, тип и ID объекта,
но не вопросы, ответы или текст записей.

## Запуск

Нужны Python 3.11+ и Node.js 20+.

```bash
cd day-11
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
npm install
npm --prefix frontend install
cp .env.example .env
# Укажите DEEPSEEK_API_KEY или OPENROUTER_API_KEY в .env
npm run dev
```

Откройте [http://127.0.0.1:5177](http://127.0.0.1:5177). FastAPI слушает
`127.0.0.1:5010`, Vite — `127.0.0.1:5177`. Ключи остаются только в backend
`.env` и не попадают в SQLite, API-ответы, preview или аудит.

Лаборатория использует `data/memory-lab.sqlite3`. При первом запуске после
обновления прежняя таблица с типами `decision`/`knowledge` автоматически
перестраивается: `id`, текст и дата каждой записи сохраняются, категория
отбрасывается.

## Сценарий: темы и источник ответа

Долговременная память предлагает две независимые записи:

1. «Ты эксперт по телевизионным сериалам и отвечаешь по экранному канону»;
2. «Ты эксперт по книгам и отвечаешь по книжному канону».

Обе подсказки доступны независимо от рабочей задачи. Кнопка только подставляет
текст в поле, а сохранение остаётся отдельным явным действием по кнопке
`Добавить`. Для чистого сравнения следует хранить одну роль эксперта за раз:
перед сменой источника удалить прежнюю запись и добавить другую.

В рабочей памяти есть две темы разговора:

1. **Задача 1 · «Игра престолов».** Рабочая память задаёт только тему разговора,
   без упоминания книжного цикла.
2. **Задача 2 · «Ведьмак».** У этой истории тоже есть книги и сериал с
   различающимися сюжетными деталями, но рабочая память хранит только тему.

Для «Игры престолов» подготовлены вопросы:

1. «Перескажи концовку.»
2. «Как звали сестру Теона Грейджоя?»
3. «Что стало с Кейтлин Старк?»

Для «Ведьмака»:

1. «Перескажи концовку.»
2. «Кем Цири приходится Геральту?»
3. «Что стало с Йеннифэр?»

Формулировки рабочих задач и вопросов намеренно не называют источник. Его
задаёт выбранная long-term-запись об экспертизе, поэтому для книжной и экранной
версии ответы будут различаться. Готовые вопросы не записываются в working
memory: они по одному подставляются в чат и становятся short-term только после
отправки. Перед первым вопросом второй задачи интерфейс предлагает создать новую
сессию.

Рекомендуемый учебный поток:

1. сохранить нужную роль эксперта в long-term;
2. выбрать «Игру престолов» и задать три готовых вопроса;
3. при необходимости заменить роль эксперта;
4. выбрать «Ведьмака», создать новую сессию и задать его три вопроса;
5. открыть preview и сравнить влияние long-term, working и short-term.

## Интерфейс

На desktop слева находятся сессии, в центре — чат, справа — долговременная и
рабочая память. Под чатом расположены метрики и безопасный аудит. На узком
экране сессии становятся верхней горизонтальной панелью, а память и статистика
располагаются после чата.

Оба изменяемых слоя используют по одному компактному полю: текст можно сразу
добавить в долговременную память или использовать как новую рабочую задачу.
Под каждым полем отдельно показано текущее состояние слоя. Выбор учебной темы
по-прежнему заполняет расширенное состояние рабочей памяти целиком.

В настройках доступны provider, model, temperature, `max_tokens` и режим
краткосрочного контекста:

| Режим | Что попадает в запрос |
| --- | --- |
| Sliding Window | Последние `N` сообщений активной сессии |
| Sticky Facts | Session-scoped JSON facts и последние `N` сообщений |
| Rolling Summary | LLM-сводка архива и последние сообщения |
| Полная сессия | Вся история активной сессии |
| Без истории сессии | Константы, long-term-записи и рабочая задача |

Sticky Facts и summaries остаются техническими снимками одной сессии и не
переносятся как профиль.

## API и границы

| Метод | Действие |
| --- | --- |
| `GET /api/state` | Слои, активная сессия, аудит и метрики |
| `POST /api/long-term` | Добавить `{ "content": "произвольный текст" }` |
| `DELETE /api/long-term/{id}` | Удалить long-term-запись |
| `PUT /api/task` | Полностью заменить рабочую задачу |
| `POST /api/sessions` | Создать и выбрать пустую сессию |
| `POST /api/sessions/{id}/activate` | Выбрать short-term scope |
| `POST /api/sessions/{id}/reset` | Удалить сообщения сессии |
| `POST /api/sessions/{id}/branch` | Создать ветку-копию сессии |
| `POST /api/memory/clear` | Очистить все три слоя и журнал `MEMORY_EVENTS`, затем открыть одну пустую сессию |
| `POST /api/ask` | Собрать контекст, вызвать модель и атомарно сохранить ход |

- Prompt — до 4 000 символов; запись или поле задачи — до 500 символов.
- Общий лимит — 40 long-term-записей и 20 сессий.
- Похожий на секрет текст отклоняется до сохранения или отправки модели.
- Ошибка провайдера не оставляет половину диалогового хода.
- Markdown ответа очищается `bleach` перед `v-html`.
- Legacy-поле `entry_type` в `POST /api/long-term` игнорируется для мягкой
  совместимости.

## Контекст модели

Preview показывает фактически отправленный безопасный JSON в порядке:

1. неизменяемые константы;
2. `Долговременная память — явные записи` с `{"entries": [...]}`;
3. рабочая задача и её ограничения;
4. summary/facts и история активной сессии согласно режиму;
5. текущий вопрос пользователя.

Пустые блоки не добавляются. Новая сессия меняет только short-term scope;
рабочая задача и long-term-записи сохраняются.

## Проверки

```bash
npm test
npm run build
```

Тесты не выполняют сетевых LLM-вызовов. Они проверяют раздельное хранение
слоёв, миграцию старой SQLite-схемы, API и лимиты свободных записей, порядок
preview, режимы контекста, сессии и ветки, атомарность при ошибках, безопасность
API и очистку Markdown. Production build проверяет Vue-интерфейс.
