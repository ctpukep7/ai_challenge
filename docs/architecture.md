# Архитектура проекта

## Веб-приложения

В поздних учебных днях браузер обращается к FastAPI, Python-агент собирает
контекст и вызывает провайдера модели. Vue отвечает за интерфейс; ключ модели
хранится только на backend. Vite используется для разработки и production build.

SQLite используется по заданию: для истории диалогов, состояния задач, индексов
или результатов. Наличие SQLite не означает, что каждый день хранит историю:
например, Day27 и Day30 сохраняют переписку только в памяти вкладки.

## RAG

RAG извлекает фрагменты документов перед генерацией ответа. Эмбеддинги
создаются локально, векторы и метаданные сохраняются в SQLite. DeepSeek получает
вопрос и выбранные фрагменты, а не весь репозиторий.

Day21–25 используют исторический корпус README корня и дней01–20.
Новая неделя использует отдельный загрузчик: README всех дней и публичную docs.
Индексы прежних дней автоматически не расширяются и не перестраиваются.

Метаданные источника включают путь, раздел и текст; новые индексы также хранят
диапазон строк и хеш исходного документа. Проверка цитаты подтверждает её
происхождение. Она не доказывает правильность смыслового вывода модели.

## MCP

MCP отделяет интерфейс инструмента от модели. Host запускает MCP-сервер и
обменивается с ним сообщениями протокола через stdio. Это отдельный процесс,
а не подстановка результатов вызова Python-функции в вымышленную трассу.

Day31 читает текущую ветку и список файлов репозитория. Day33 читает
синтетические тикеты и связанного пользователя. Эти инструменты не изменяют
файлы, ветку, данные тикетов или учётные записи.

В расширенном Day31 модель получает обнаруженный каталог MCP-инструментов и
сама выбирает поиск документации, ветку, список файлов, чтение исходника или
diff. Сервер проверяет имя и аргументы, выполняет разрешённый read-only вызов и
возвращает результат модели. Цикл ограничен количеством шагов и объёмом данных.
Git-изменения включают отдельные помеченные снимки новых разрешённых файлов;
исключённые пути и усечение отмечаются явно.

## Доверенные и недоверенные данные

Тексты README, код PR, имена веток и сообщения тикетов могут содержать
инструкции. Они рассматриваются как данные, а не системные команды.
Входные данные модели не должны давать доступ к shell или секретам.
Факты из документов и свежие сведения MCP показываются отдельно.
