# API ассистентов новой недели

## Day31: вопросы разработчика

`POST /api/help` принимает `question` и необязательный `history` — до четырёх
полных пар сообщений с ролями user/assistant и текстом content.
Команда `/help` без аргументов запрашивает обзор проекта; `/help <вопрос>`
и обычный вопрос проходят один RAG-пайплайн.

Успешный ответ содержит `status`, `answer`, `sources`, `context` и `trace`.
`sources` — подтверждённые документальные фрагменты с цитатой, путём и строками.
`context` — результаты выбранных MCP-инструментов; `trace` показывает реальные
discovery, вызовы и отклонённые host-запросы с отдельной пометкой. Модель сама
выбирает поиск документации, Git, чтение исходника и diff из каталога MCP.
`warnings` сообщает, например, о недоступности инструмента или ограничении данных.
`metrics` содержит время, число модельных/MCP-вызовов и реальные usage токены;
если провайдер не сообщил usage, соответствующие значения остаются null.
Источники имеют вид документации, кода, Git или diff и проверенную цитату.

`GET /api/index` возвращает состояние индекса, количество документов и чанков.
`POST /api/index/build` обновляет индекс из разрешённого корпуса.
Параллельные запросы генерации или обновления отклоняются с HTTP409.

## Day33: вопросы поддержки

`GET /api/tickets` возвращает список вымышленных тикетов через MCP.
`POST /api/support/ask` принимает `ticket_id`, `question` и историю текущего
тикета. Backend получает через MCP тикет и связанного пользователя.
История от другого тикета не принимается.

Документальные источники ответа и сведения тикета показаны отдельно.
Смена выбранного тикета очищает беседу в интерфейсе.
Индекс справки имеет собственные `/api/index` и `/api/index/build`.

## Day32: интерфейс автоматического ревью

Day32 не предоставляет отдельный веб-сервер. Его интерфейс — CLI и workflow
GitHub Actions. Вход: номер PR и GitHub-репозиторий; снимок включает base/head SHA,
изменённые файлы и diff. Выход: Markdown, JSON и обновляемый комментарий в PR.
Точные команды CLI и настройка Secret описаны в README Day32.

## Ошибки и ограничения

Неверный вход отклоняется до обращения к модели. Недостаток документальных
свидетельств обозначается статусом unknown. В Day31 ошибка выполнения возвращает
status=error с сохранёнными trace и metrics; такой ответ не добавляется в историю.
В Day33 сбой провайдера возвращается HTTP-ошибкой.
Отсутствие индекса или его устаревание требует построения/обновления индекса.
Ключ DeepSeek никогда не включается в тело ответа, источники и трассу MCP.
