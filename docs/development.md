# Разработка и проверки

## Работа с отдельным днём

Перед запуском прочитайте README нужного дня. Порты и состав зависимостей
отличаются. Не запускайте все приложения одновременно без необходимости.
Изменения одного задания не должны незаметно менять поведение другого.

Backend — Python, поздний frontend — Vue/Vite. README и интерфейсы написаны
на русском языке. Для Day31–33 общие компоненты оформлены как устанавливаемый
пакет; для установки с другого компьютера используется lock зависимостей.

## Секреты и данные

API-ключи передаются через переменные окружения или локальный `.env`.
Содержимое `.env` не добавляется в Git, RAG-корпус, JSON-трассы и сообщения
об ошибках. `.env.example` содержит только названия параметров и заглушки.
Веса моделей, окружения, базы, результаты и видео не публикуются.

## Проверки

Backend-тесты проверяют контракты API, источники, ошибки и работу инструментов.
Frontend-тесты проверяют состояние интерфейса; production build проверяет
сборку. Браузерная проверка отдельно оценивает основной сценарий и мобильную
ширину. Поддельный транспорт удобен для ошибок, но не доказывает работу API
настоящей модели или GitHub Action.

## Автоматическое ревью Day32

Ревью использует diff и RAG-контекст, показывает возможные баги, архитектурные
проблемы и рекомендации. Оно не запускает код PR и не исправляет его.
Проверенные пути и строки не делают смысл замечания автоматически верным.
Отсутствие замечаний не является гарантией отсутствия ошибок.

Workflow запускает доверенный код из базовой ветки. Содержимое PR остаётся
текстом для анализа. Fork PR в первой версии не анализируются автоматически.
Результат относится к конкретному head SHA и обновляется при новом коммите.
