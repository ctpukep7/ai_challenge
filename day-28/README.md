# День 28 — локальная LLM + RAG

Задайте вопрос о README проекта. Приложение ищет подходящие фрагменты в готовом
индексе недели RAG и передаёт их локальной Qwen3 4B через Ollama. Обычная
отправка выполняет поиск и генерацию на ноутбуке.

Отдельная кнопка **«Сравнить с DeepSeek»** отправляет один вопрос и одинаковые
найденные фрагменты обеим моделям. Инструкции, temperature и лимит ответа также
одинаковы. Рядом показываются непосредственные ответы и время каждой модели.
Вопрос и выбранные README-фрагменты при этом передаются сервису DeepSeek.
История предыдущих вопросов не отправляется. Каждое нажатие сравнения создаёт
новые ответы обеих моделей; архивные ответы в интерфейсе не показываются.

## Соответствие заданию Day28

- **Индекс недели 6:** используется существующий `day-21/data/index.sqlite`,
  без пересборки или копирования. Это сохранённый снимок README, который
  может отличаться от сегодняшнего кода.
- **Локальная цепочка:** FastEmbed, поиск и обычная генерация `/api/ask`
  работают локально; загрузка embedding-модели из сети отключена.
- **Сравнение с облаком:** `/api/compare` даёт два свежих ответа на одинаковые
  сообщения и фрагменты. Сохранено шесть живых сравнений с DeepSeek: один
  UI-прогон и пять CLI-прогонов. Облачный режим включается отдельно.
- **Качество, скорость, стабильность:** ниже приведены ручная сверка с
  источниками, раздельное HTTP-время и три повтора одного вопроса.
  Нулевые API-ошибки не выдаются за отсутствие смысловых ошибок.
- **Результат:** полностью локальный RAG работает независимо от опционального
  облачного сравнения. `/api/ask` проверен с запретом внешней сети.

Перепроверка 12 октября 2026: прошли 62 backend и 31 frontend тест,
production build; индекс прошёл SQLite `quick_check`. Новых платных облачных
запросов не выполнялось. Разделы про архив Day24 и первый локальный прогон
описывают историю; текущая демонстрация — прямое сравнение без архивных карточек.

## Запуск

Из корня проекта:

```sh
cd day-28
npm run serve
```

Откройте [локальный RAG](http://127.0.0.1:5027/). Готовая сборка работает без Vite.
Для разработки — `npm run dev`, интерфейс на `http://127.0.0.1:5194/`.
Остановка — Ctrl+C в терминале запуска. Работающий Ollama переиспользуется;
если его нет, launcher явно запускает сервер Day26 и останавливает только
свои процессы. Никакого автозапуска macOS.

Используются уже установленные компоненты:

- Python-окружение `day-21/.venv` с FastEmbed, FastAPI, HTTPX и uvicorn.
- Индекс `day-21/data/index.sqlite`, открытый только для чтения.
- Embedding-кэш `day-21/.cache/fastembed`.
- Vue/Vite из Day27 через ссылку `frontend/node_modules`.
- Единственные веса Qwen3 Instruct 4B и runtime Ollama из Day26.

Новые Python-окружения, зависимости и веса для текущего ноутбука не нужны.
Проверяйте общий бюджет недели 8 ГБ перед любой дополнительной установкой.

Если ссылка на frontend-зависимости отсутствует, из `day-28` выполните:

```sh
ln -s ../../day-27/frontend/node_modules frontend/node_modules
npm run build
```

Для другого компьютера сначала восстановите индекс, embedding-кэш и окружение
по [README Day21](../day-21/README.md), runtime и веса — по
[README Day26](../day-26/README.md), frontend-зависимости — по
[README Day27](../day-27/README.md). Day28 сам не пересобирает индекс и не
скачивает embedding-модель. `requirements.txt` описывает backend-зависимости;
launcher использует именно `day-21/.venv`. Для обычного локального режима облачный ключ не нужен.

## Собственные вопросы и источники

Введите вопрос, например: «Какой transport использует локальный MCP server
в дне 16?». Enter отправляет вопрос, Shift+Enter добавляет строку. Готовый вопрос
можно подставить и отредактировать; выбор сам не запускает генерацию.

Каждый вопрос ищется **отдельно**. Предыдущие ответы остаются на экране, но не
передаются модели: это помогает сравнивать одинаковые вопросы независимо от
истории. Указывайте номер дня прямо в вопросе. Очистка экрана удаляет только
данные текущей вкладки; обычные беседы не сохраняются на диск.

Под ответом раскрываются реальные фрагменты, переданные модели: файл, раздел,
идентификатор чанка и полный текст. У опорного фрагмента есть cosine score,
у соседнего — отдельная отметка без выдуманного score. Ссылки `[1]` относятся
к этим фрагментам. Наличие ссылки само по себе не доказывает, что модель
правильно поняла источник; смысл ответа нужно проверять.

Модель получает короткую инструкцию отвечать по источникам. При слабом поиске
приложение отвечает «Не знаю» без генерации. Ошибки API показываются отдельно,
вопрос восстанавливается для ручного повтора. Автоматических повторов нет.

## Генерация и ограничения

Ollama доступен только на `127.0.0.1:11434`, облачные функции отключены при
запуске Day26. Модель: `qwen3:4b-instruct-2507-q4_K_M`, `think=false`,
`temperature=0.7`, `num_predict=1024`, `num_ctx=4096`, `keep_alive=1m`.
Одна генерация одновременно, таймаут 120 с. Длинный ответ может обрезаться;
интерфейс сообщает об этом. Компактная модель может ошибаться или повторяться.

Вопрос ограничен 500 символами и 1000 UTF-8 байтами; дополнительно действует
лимит токенизатора embedding-модели. Контекст собирается из целых чанков до 6000
UTF-8 байт. Это консервативный текстовый бюджет, не точный подсчёт токенов Qwen.

## Прямое сравнение с DeepSeek

Обычные Enter и кнопка отправки используют `/api/ask` и обращаются только
к локальной модели. Для сравнения нажмите отдельную кнопку: `/api/compare`
один раз выполняет поиск и собирает контекст, затем параллельно отправляет
одинаковые `system`/`user` сообщения Qwen и DeepSeek. Для каждой модели
используется `temperature=0.7`, максимум 1024 выходных токена и отключённый
thinking. Внутренние шаблоны и токенизаторы различаются, поэтому одинаковый
текст не означает одинаковое число входных токенов.

Облачный клиент читает `DEEPSEEK_API_KEY` и `DEEPSEEK_MODEL` из переменных
процесса, собственного локального `.env` Day28 или существующего `.env` Day24.
Ключ не копируется в код или документы. Если модель не задана, используется
`deepseek-flash`. Для другого компьютера можно задать конфигурацию в `day-28/.env`:

```dotenv
DEEPSEEK_API_KEY=ваш_ключ
DEEPSEEK_MODEL=deepseek-flash
```

Этот файл исключён из Git; перезапустите приложение после изменения настройки.
Если ключа нет, обычный локальный RAG работает, сравнение недоступно.
Состояние «настроено» означает наличие конфигурации; реальная доступность
проверяется только при нажатии кнопки. Облачные вызовы требуют интернета и
оплачиваются по тарифу провайдера. Дополнительных локальных весов не нужно.

Обе карточки показывают непосредственные ответы без дополнительного verifier.
Статус `answered` и ссылки `[n]` не доказывают фактическую правильность.
Проверять нужно полноту, соответствие источникам и отсутствие выдуманных
условий. Ошибка или таймаут одной модели не скрывают успешный ответ другой;
архив вместо ошибки не подставляется. Повторный запрос выполняется вручную.
При пустом контексте генерации не запускаются, в том числе облачная.

Общий поиск измеряется один раз. Для сравнения скорости используйте **HTTP-время
каждой модели**, которое включает обработку входа и получение ответа.
Чистое время генерации Ollama показывается дополнительно; DeepSeek отдельного
времени вычислений не сообщает, поэтому это поле для него не выдумывается.
Исходные сообщения сравнения имеют общий SHA256 в API; тесты дополнительно
перехватывают оба тела запроса и проверяют точное совпадение сообщений.

Под каждым ответом постоянно виден одинаковый блок «Статистика ответа»:
полное время, HTTP-время, поиск контекста, загрузка embeddings, признак первого
поиска, загрузка модели, генерация, входные/выходные/все токены, скорость
получения ответа, чистая скорость генерации и количество фрагментов.
В обеих карточках показан один и тот же общий поиск; он выполняется один раз.
Полное время каждой модели считается до её собственного ответа, а не до
завершения более медленного запроса. Загрузка embeddings уже входит в поиск:
их длительности не нужно суммировать.

Скорость получения ответа — выходные токены / полное HTTP-время этой модели;
она включает обработку входа и ожидание ответа. Это одинаковая формула для
обоих провайдеров, однако токенизаторы различаются. Чистая скорость генерации
Ollama — выходные токены / время генерации. У облака эти разные показатели
не подменяются друг другом: отсутствующие load/eval данные помечены
«Не предоставлено». При ошибке — «Нет данных», при пропуске генерации —
«Не выполнялось». Измеренный ноль отображается как ноль, а не отсутствие данных.


API-ключи, заголовки авторизации и сырые ошибки провайдера не возвращаются
в интерфейс и не записываются в отчёты. Облачный адрес фиксирован:
`https://api.deepseek.com/chat/completions`; перенаправлений, proxy из окружения
и автоматических повторов нет. Сравнение занимает один слот приложения,
как и обычный локальный запрос; общий таймаут — 120 с.

## Архив исследования: данные Day24

`data/cloud-baseline.json` содержит 10 синтетических ответов из сохранённого
`day-24/data/benchmark-live-reviewed.json`. Эти данные сохранены только для разбора предыдущих экспериментов.

Day24 использовал другой prompt и отдельную проверку утверждений; точный тег
модели и время не сохранены. Его отказ может означать отклонение утверждения
проверяющим этапом при найденном контексте, а не отсутствие retrieval.

Например, q01 имел четыре фрагмента, но одно утверждение о `localStorage` не
прошло проверку, после чего весь опубликованный ответ стал «Не знаю».
Все 40 опорных чанков архивного прогона совпали по ID и тексту с индексом Day21;
это подтверждает совместимость свидетельств, не равенство двух пайплайнов.

Если локальный архив сохранился, команда `npm run export-baseline` восстанавливает
файл без вызова модели. Отсутствие архива не
мешает локальным ответам и прямому сравнению. `data/` не публикуется в Git.

## Исходный локальный прогон — 11 октября 2026

Из `day-28`:

```sh
npm test
npm run build
npm run benchmark -- --output data/benchmark-local.json
```

Прошли 41 backend-тест и 11 frontend-тестов, production build. Проверены
ошибки HTTP/JSON/таймаута, отсутствие модели/кэша, ограничения вопроса и
контекста, отсутствие повторов и облачных переходов, реальный состав источников,
отказы без генерации и блокировка второго запроса. При таймауте retrieval-поток
сохраняет слот до своего завершения. Тесты используют поддельный транспорт и
временный индекс; ожидаемые факты не передаются модели.

Живой последовательный прогон: 10 одинаковых вопросов из Day22/24,
вопрос о несуществующем Day99 и три дополнительных повтора q03. Всего 14
запросов, около 126 секунд, **0 ошибок API и 0 обрезанных ответов**.
Основные вопросы: 9 `answered`, 1 `unknown`; архив Day24: 8 и 2 соответственно.
Эти статусы не являются оценкой правильности.

После предварительного холодного вопроса контрольные ответы занимали
4,67–13,22 с, медиана 11,44 с. Поиск: 0,046–0,086 с, медиана 0,060 с;
генерация: 4,40–7,27 с, медиана 6,24 с. Скорость генерации — примерно
28–32 токена/с. `http_seconds` включает обработку prompt и ожидание Ollama,
поэтому оно больше чистого времени генерации. В первом вопросе через UI
поиск занял 0,59 с (из них загрузка embeddings 0,55 с), загрузка LLM —
2,06 с, генерация — 5,82 с, полный запрос — 13,97 с. Холодное время не
смешивается со временем прогретого прогона.

Проверка содержания выявила ограничения:

- q01: модель описала SQLite и загрузку истории перед запросом.
- q02: пропущено важное различие первого и позднего сбоя summary;
  часть нужных фрагментов не попала в контекст, а доступное описание позднего
  сбоя модель не использовала.
- q05: отказ — необходимые условия конфликта не попали в выбранные фрагменты.
- q06: транспорт `stdio` найден; в отдельном первом ответе модель ошибочно
  перенесла отсутствие сети в тестах на весь локальный MCP-сценарий.
- q08: модель смешала системный cron-диспетчер и расписание заданий в SQLite.
- q09: alias назван правильно, но перепутано имя для модели и имя на проводе MCP.
- q10: три условия перехода перечислены правильно, добавлены ненужные сомнения.

Все четыре ответа q03 назвали Sliding Window, Branching и Sticky Facts,
но затем добавляли противоречивые оговорки о нехватке данных. Формулировки и
скорость менялись: 6,09–8,67 с. Это устойчивое перечисление названий,
**не доказательство стабильной корректности всего ответа**. Эвристика aliases
нашла 14 из 27 ожидаемых фактов в основном прогоне; она пропускает перефразы
и не выявляет ложные утверждения. Независимого семантического валидатора нет.
Архив облака использовал другой pipeline, поэтому ранжировать модели по этим
числам нельзя. Облачное время и повторные прогоны не сохранены.

без генерации, тогда как более точная формулировка о контексте после перезапуска
