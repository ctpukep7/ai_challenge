# Day 02 — Контроль ответа DeepSeek

Это задание показывает, как настройки формата, длины, условия завершения и thinking mode меняют ответ DeepSeek API.

## Сценарий

1. Введите свой промпт и нажмите «Отправить».
2. При необходимости откройте кнопку с шестерёнкой и задайте настройки.
3. Отправьте промпт ещё раз — блок ответа заменится новым результатом.

На странице отображается одно JSON-превью следующего запроса и один блок ответа. API-ключ в браузер не передаётся.

## Настройки

- **Формат ответа** — свободная текстовая инструкция для модели, например «Краткий заголовок и ровно 3 маркированных пункта».
- **Длина ответа** — официальный параметр API `max_tokens`, ограничивающий число генерируемых токенов.
- **Условия завершения** — официальный параметр `stop`. Кнопка `＋` добавляет новое поле для маркера; DeepSeek принимает до 16 уникальных маркеров за запрос. API завершает ответ на первом встретившемся маркере и не выводит его в тексте.
- **Thinking mode** — по умолчанию выключен, чтобы лимит токенов расходовался на видимый ответ. Его можно включить или оставить выбор DeepSeek.

Текстовые поля настроек изначально пусты и не добавляются в API-запрос. Thinking mode по умолчанию передаётся как `disabled`. После ответа интерфейс показывает число выходных токенов, `finish_reason`, статус thinking mode и число reasoning-токенов без внутреннего текста рассуждений.

## Подготовка

Нужны Python 3.10+ и ключ из [DeepSeek Platform](https://platform.deepseek.com/api_keys).

Команды выполняются из `day-02` (из корня проекта сначала выполните `cd day-02`).

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Создайте `.env` в папке дня и добавьте ключ:

```text
DEEPSEEK_API_KEY=ваш_ключ_DeepSeek
```

Файл `.env` не попадает в Git.

## Запуск

```bash
python3 app.py
```

Откройте [http://127.0.0.1:5001](http://127.0.0.1:5001).


## Устройство запроса и ограничения Day 02

В Day 02 «Контроль ответа» браузер отправляет `POST /ask` с полями `prompt` и `settings`. Сервер вызывает `deepseek-v4-flash` через OpenAI-совместимый клиент и `https://api.deepseek.com`. Инструкция формата и требование написать stop-маркер объединяются в сообщение `system`, затем идёт исходный вопрос с ролью `user`. «Формат ответа» — текстовая инструкция, а не JSON Schema или проверка структуры: приложение не исправляет ответ, нарушающий формат.

В Day 02 допустимый явный `max_tokens` — от 1 до 10 000; пустое значение не отправляется провайдеру. Это предел токенов генерации, а не слов или символов. Сервер удаляет пустые stop-маркеры и повторы, оставляя не более 16 уникальных строк. Поле thinking принимает `disabled`, `enabled` или пустую строку: последняя исключает параметр из запроса, оставляя выбор API. JSON-превью в браузере описывает текущие поля до серверной нормализации; например, повторяющиеся stop-маркеры сервер уберёт перед вызовом.

В Day 02 нет истории диалога и постоянного хранения настроек: при повторной отправке блок результата заменяется, после обновления страницы настройки возвращаются к исходным. Видимый ответ приходит целиком и отображается как текст. Внутренний текст reasoning не показывается; метаданные берутся из `usage` и `finish_reason`, а отсутствующие значения отображаются прочерком. Пустой финальный текст при `finish_reason=length` объясняется исчерпанным лимитом с предложением увеличить `max_tokens` или выключить thinking.

Day 02 возвращает HTTP 400 для неверного вопроса или настроек, HTTP 503 при отсутствии ключа и HTTP 502 при ошибке DeepSeek. Для демонстрации сравните один вопрос с пустыми настройками, затем с форматом «ровно 3 пункта» и лимитом 120, затем с stop-маркером. Сверяйте текст, превью и причину завершения: соблюдение инструкции оценивает человек. Запуск использует локальный Flask debug server, отдельная сборка frontend не требуется.

## Проверка Day 02

Из папки `day-02` после установки зависимостей выполните:

```bash
.venv/bin/python -m unittest -v
```

Тесты `test_app.py` подменяют клиент модели и проверяют параметры запроса, обработку лимита и ошибок; они не подтверждают доступность внешнего API или качество реального ответа.
