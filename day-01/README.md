# Минимальный веб-чат с DeepSeek

Приложение принимает один вопрос в браузере, отправляет его в DeepSeek API и показывает ответ. История диалога не сохраняется.

## Подготовка

Нужны Python 3.10+ и ключ из [DeepSeek Platform](https://platform.deepseek.com/api_keys).

Команды выполняются из папки `day-01` (из корня проекта сначала выполните `cd day-01`).

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Создайте файл `.env` в папке дня и вставьте ключ после знака `=`:

```text
DEEPSEEK_API_KEY=ваш_ключ_DeepSeek
```

Не добавляйте ключ в `app.py` и не публикуйте файл `.env`.

## Запуск

```bash
python3 app.py
```

Откройте в браузере [http://127.0.0.1:5000](http://127.0.0.1:5000), введите вопрос и нажмите «Отправить».

## Что происходит

Браузер отправляет текст на локальный маршрут `/ask`. Python-сервер берёт ключ только из переменной окружения, вызывает модель `deepseek-v4-flash` через `https://api.deepseek.com` и возвращает текст ответа в браузер.


## Контракт запроса и ограничения Day 01

В Day 01 «Первый запрос к LLM» Flask обслуживает и страницу `GET /`, и JSON-маршрут `POST /ask`. Браузер отправляет объект `{"prompt": "текст вопроса"}`; сервер убирает пробелы по краям и передаёт ровно одно сообщение с ролью `user`. Ответ API приложения имеет поле `answer`. Настройки `temperature`, `max_tokens`, `stop` и thinking приложение не задаёт: их поведение определяется провайдером. Текст отображается как обычный текст с сохранением переносов строк, без Markdown и потоковой выдачи.

Day 01 не хранит сообщения в базе, файлах или браузерном хранилище. Следующий вопрос отправляется самостоятельно, без предыдущего вопроса и ответа; видимый результат заменяется. Поэтому просьба «продолжи предыдущий ответ» сама по себе не передаёт модели прошлый контекст. Пока идёт запрос, кнопка отправки отключена.

В Day 01 пустой вопрос, неверный тип `prompt` или отсутствующий JSON возвращают HTTP 400. Отсутствие `DEEPSEEK_API_KEY` даёт HTTP 503, ошибка вызова провайдера — HTTP 502 с общим сообщением о недоступности. Пустой ответ модели превращается в поясняющий текст в поле `answer`. При ошибке связи браузер показывает сообщение о локальном сервере. Приложение запускается на loopback с Flask debug mode: это учебный локальный сервер.

Для демонстрации Day 01 отправьте короткий вопрос и затем новый самостоятельный вопрос: оба ответа должны появиться в одном блоке. Здесь не предусмотрены собственные автоматические тесты, отдельный frontend или production build; запуск описывает конфигурацию исходников, а доступность модели и качество живого ответа требуют отдельного запроса с действующим ключом.
