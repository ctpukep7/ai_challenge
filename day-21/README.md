# День 21 — индексация документов

Первый шаг RAG: локальный набор документов превращается в чанки двух типов, векторы
FastEmbed и проверяемый SQLite-индекс. Веб-интерфейс показывает реальные этапы
сборки, сравнение и поиск. Генерации ответов LLM здесь ещё нет.

## Корпус

Источник — **отслеживаемые Git файлы текущего проекта**: корневой `README.md`
и `day-01/README.md` … `day-20/README.md`. Список определяется `git ls-files`,
сортируется и проверяется перед чтением. README дней 21–23 исключены, чтобы
описание самого RAG не участвовало в контрольных вопросах. Неотслеживаемые
файлы, локальные заметки, отчёты, PDF и `.env` не индексируются.

Каждый README становится документом с полным относительным `source`, например
`day-18/README.md`; Markdown-заголовки выделяют разделы. Содержимое берётся из
рабочей копии, поэтому изменение README делает существующий индекс устаревшим.
SHA-256 учитывает список источников, полные относительные пути и байты файлов.
Отсутствующий отслеживаемый README и символическая ссылка вызывают явную ошибку.

Корпус доступен сразу после клонирования. Сборка требует минимум 10 000 слов
(20 условных страниц по 500 слов); точный объём виден в интерфейсе и манифесте.
Старые книжные индексы требуют пересборки. Пользовательские PDF и извлечённые
файлы сохраняются локально и больше не используются этим пайплайном.

## Установка и запуск интерфейса

Нужны Python 3.12, Node.js 20+ и Git. Из каталога `day-21`:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
npm --prefix frontend ci
npm run dev
```

Откройте [интерфейс](http://127.0.0.1:5187). Backend доступен на
`http://127.0.0.1:5020/docs`; остановка — `Ctrl+C`. Серверы слушают только
`127.0.0.1`. Корневой `npm run dev` запускает FastAPI и Vue/Vite вместе.
Если отслеживаемые README отсутствуют, страница покажет причину, а сборка
останется недоступной до восстановления файлов.

Первая сборка индекса скачивает открытую модель
`sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` в
`day-21/.cache/fastembed/` (около 0,22 ГБ); после этого inference локальный,
без API-ключа. Поиск использует тот же кэш модели.
При недоступной сети на первом запуске сборка не завершится.

### Демонстрация в браузере

Для **видео без голоса и монтажа** включите запись экрана, откройте интерфейс и
нажмите **«Начать показ»** в первом экране. Страница сама переходит от корпуса к
исходному документу, очищает **отдельный демонстрационный индекс**
`data/demo-index.sqlite` и показывает первый прогон: файла нет, 0 чанков и
0 эмбеддингов. Только после этого она запускает настоящую сборку. Основной
`data/index.sqlite` остаётся на месте. После завершения сборки
автопоказ задерживается на трёх отдельных кадрах пайплайна: **разбиение**
(`fixed` и `structure`, число чанков и границы разделов), **эмбеддинги** (число
сохранённых векторов, размерность и модель), **SQLite** (файл, таблицы и число
прочитанных строк). Затем он показывает сравнение стратегий, раскрывает чанк
с метаданными и выполняет семантический поиск по демонстрационному индексу.
Числа в кадрах читаются из текущего сохранённого индекса.
Крупные подписи на экране поясняют каждый шаг; финальная подпись остаётся до
закрытия. Во время выдержек можно нажать **«Далее»**, а **«Остановить показ»**
завершает автопереходы. Если остановить показ во время сборки, начатая сервером
сборка продолжится. Повторный показ снова начинает с пустого demo-файла;
кнопка **«Вернуться к основному индексу»** переключает просмотр обратно.
Приложение не записывает видео: достаточно стандартной записи экрана на
компьютере.

При ручной демонстрации:

1. Нажмите **«Подготовить пустой индекс»**. Это удалит только отдельный
   демонстрационный SQLite-файл. На экране появятся «Нет индекса», 0 чанков и
   0 эмбеддингов; основной индекс останется готовым. Для повторения первого
   прогона после сборки нажмите эту кнопку ещё раз.
2. В разделе **Корпус документов** выберите один из README-файлов: справа
   отображаются его разделы, число слов и фрагмент README.
3. В разделе **Пайплайн индексации** нажмите **«Построить индекс»**. Можно
   изменить перекрытие в пределах 0–40%. Журнал показывает реальные этапы:
   чтение, загрузку модели, два вида разбиения, число сохранённых эмбеддингов
   и проверку SQLite. Под журналом есть три карточки с измеренными результатами
   каждого этапа. Процент отображается только на измеримых этапах.
   Повторный запуск во время сборки отклоняется; при ошибке основной индекс
   остаётся доступным, а demo-индекс остаётся пустым, если это был его первый прогон.
4. В **Сравнении** покажите количество, длины и перекрытие чанков, затем
   различие границ: `fixed` может объединить конец одного раздела с началом
   другого, `structure` сохраняет границы разделов.
5. В **Просмотре чанков** переключите стратегию и источник. Раскройте строку:
   видны текст, `source`, `title`, `section`, `chunk_id`, число токенов и
   размерность сохранённого вектора.
6. В **Семантическом поиске** выберите пример «Как системный cron и расписания SQLite работают вместе в Day 18?»
   или «Что происходит с историей Day 07 при ошибке API?». Оба столбца показывают top-k из одного
   запроса для двух стратегий, включая score и метаданные.

Открытие страницы не загружает модель: сведения о готовом индексе читаются
из SQLite. По умолчанию показан основной индекс; выбранный demo-режим не
сохраняется в браузере после перезагрузки страницы, но созданный demo-файл
остаётся на диске до нового чистого прогона. Состояние текущей сборки живёт
в памяти процесса, а индекс сохраняется после перезапуска сервера. Это
локальный учебный стенд для одного пользователя; данные корпуса не отправляются
во внешний API.

### CLI и проверки

```sh
.venv/bin/python main.py build
.venv/bin/python main.py compare
.venv/bin/python main.py search "Что происходит с историей Day 07 при ошибке API?" --strategy both
.venv/bin/python -m pytest tests
npm run test:frontend
npm run build
```

По умолчанию индекс находится в `data/index.sqlite`. Путь можно заменить общим
параметром **перед** командой: `main.py --db /tmp/readmes.sqlite build`.
`build` создаёт временную БД рядом с целевой и заменяет старый индекс только
после успешной записи, чтения всех векторов и `PRAGMA integrity_check`.

## Разбиение и метаданные

Обе стратегии получают одинаковый текст README каждого документа. `fixed` режет каждый файл на
последовательные окна до 126 токенов текста с перекрытием 18%; такой чанк может
пересечь границу разделов. `structure` сначала выделяет разделы по Markdown-заголовкам,
затем режет каждый раздел теми же окнами, не смешивая разделы. Два служебных токена
оставлены модели с общим лимитом 128. Для каждого фрагмента длина повторно
проверяется реальным токенизатором модели; неожиданный API токенизации вызывает
ошибку вместо тихого усечения. Заголовок файла хранится как `title`, но не
образует отдельный чанк.

SQLite содержит `manifest` (модель, версия FastEmbed, размерность, параметры, SHA-256 корпуса,
число файлов, разделов, слов и чанков) и `chunks`: `source`, `title`, `section`,
`chunk_id`, `strategy`, `ordinal`, текст, длину, перекрытие, отметку пересечения
разделов и вектор `float32` в BLOB. ID зависит от стратегии, источника, порядкового
номера, текста и параметров, поэтому повторная сборка на том же корпусе даёт
те же ID. При чтении проверяются модель, размерность и конечность векторов. API
также сверяет SHA-256 текущего корпуса с манифестом: индекс от прежних
документов помечается устаревшим, и поиск доступен только после пересборки.

`search` кодирует запрос той же моделью и выполняет точный cosine-поиск по
сохранённым векторам. Для небольшого учебного корпуса достаточно линейного
сканирования; SQLite здесь не выполняет ANN-поиск.

Перед cosine-поиском применяется ограничение источников из исходного вопроса.
Явные `Day 07`, `day-07/README.md`, «день 7», «в дне 7» выбирают README
указанного дня; несколько явно указанных дней объединяются. Без номера дня
поиск охватывает весь корпус. Отрицание источника и неоднозначная альтернатива
не задают ограничение; неизвестный день даёт пустое извлечение. API возвращает
`retrieval_scope` (`kind`, `sources`, `reason`), интерфейс показывает выбранные
источники. SQL ограничивает кандидатов до расчёта cosine; сами оценки не меняются.
Ограничение не использует контрольные ответы или `question_id`.


## Сравнение

`compare` берёт данные из сохранённого индекса и показывает для каждой стратегии:
число чанков, min/median/p95/max токенов, суммарное число продублированных
токенов перекрытия и число чанков, пересекающих границы разделов. P95 — ближайший
ранг `ceil(0.95 × N)`. Затем три одинаковых запроса к обеим стратегиям показывают
top-3 с `source`, `section`, `chunk_id`, cosine score и фрагментом текста.
Это описательное сравнение: без размеченного набора «запрос → релевантный раздел»
оно не доказывает, что какая-либо стратегия лучше.

Актуальные числа файлов, разделов, слов и чанков показывает сохранённый индекс.
Для проверки качества поиска подготовлены контрольные вопросы Day 22 по этим
же README. Cosine score сам по себе не подтверждает правильность ответа.

Индекс, кэш, виртуальное окружение и временные файлы исключены из Git.

## Проверенный текущий корпус

После сверки документации дней 01–20: 21 README, 180 разделов,
23 291 индексируемое слово — около 46,58 условной страницы по 500 слов.
Основные индексы дней 21–23 перестроены и имеют одинаковый SHA-256:
488 fixed и 526 structure чанков, 384-мерные векторы. SQLite integrity check
проходит во всех трёх базах. README этих трёх дней в корпус не входят.

Проверено: 50 Python-тестов, 7 frontend-тестов, production build и запуск
обоих серверов. Визуальная проверка браузера недоступна по политике инструмента.

### Примеры для записи демонстрации

Кнопки и CLI используют три проверенных запроса:

- «Как системный cron и расписания SQLite работают вместе в Day 18?»
- «Что происходит с историей Day 07 при ошибке API?»
- «Как в Day 20 реестр разделяет одинаковые имена MCP-инструментов?»

В актуальном основном и demo-индексе первый результат обеих стратегий
содержит сведения по этим вопросам. Это подобранные примеры для показа,
а не независимая оценка качества поиска. Контрольные вопросы Day 22 не менялись:
при top-5 попадание ожидаемого раздела остаётся 7/10 у обеих стратегий.
Автопоказ выводит три результата. Карточки позволяют раскрыть полный текст
чанка: короткое превью может скрывать предложение с нужным фактом.
