# Day34 · Pipeline · Ассистент работы с файлами

Ассистент получает цель, сам выбирает файлы AI Challenge и вызывает реальные локальные инструменты. Можно исследовать связи между исходниками или подготовить Markdown-документ по коду. Результат изменения сначала показывается как diff; кнопка «Сохранить» записывает его на диск.

Это отдельное приложение Day34. Старые приложения и их окружения оно не изменяет. MCP здесь не используется: задание разрешает доступный tooling, поэтому реализован локальный исполнитель файловых инструментов, вызываемых моделью DeepSeek.

## Запуск

Из корня checkout, Python 3.12 и Node.js 20+:

```bash
python3.12 -m venv .assistant-venv
.assistant-venv/bin/python -m pip install -r packages/assistant_core/requirements.lock.txt
.assistant-venv/bin/python -m pip install --no-deps -e packages/assistant_core
cp day-34/.env.example day-34/.env
```

Заполните `DEEPSEEK_API_KEY` в локальном `day-34/.env`. Модель по умолчанию — `deepseek-flash`. Если `.assistant-venv` уже создан для Day31–33, переиспользуйте его. Новые веса моделей не загружаются: здесь нет embedding-индекса и RAG, файлы читаются непосредственно инструментами.

Production:

```bash
cd day-34/frontend
npm ci
npm run build
cd ..
../.assistant-venv/bin/python -m uvicorn backend.app:app --host 127.0.0.1 --port 5033
```

Открыть http://127.0.0.1:5033/. После сборки frontend backend отдаёт его с того же адреса. Для разработки отдельно запустите backend указанной командой и `npm run dev` из `day-34/frontend` — Vite на http://127.0.0.1:5199/ проксирует `/api` на backend. Перезапустите backend, если впервые собрали `frontend/dist` после его запуска.

В папке `day-34` также доступны команды-обёртки: `npm start` запускает production backend, `npm run build` собирает UI, `npm test` проверяет backend/frontend; `npm run dev` запускает режим разработки, описанный в `package.json`.

## Удобство интерфейса

Итог ассистента отображается как Markdown: заголовки, списки, выделения, код,
цитаты и таблицы. У подготовленного документа есть отдельный раскрываемый
предпросмотр; исходный текст до/после и unified diff доступны без преобразований.
HTML экранируется, внешние изображения не загружаются; активны только ссылки
HTTP/HTTPS и якоря. Парсер — зафиксированный `markdown-it 15.0.2`.

- `Enter` в поле цели запускает задачу.
- `Ctrl+Enter` и `Shift+Enter` добавляют новую строку в текущую позицию.
- `Esc` возвращает фокус в поле цели, когда задача не выполняется; он не отменяет запрос и не очищает результат.
- `Tab` / `Shift+Tab` перемещают фокус, `Enter` / `Space` работают с кнопками и раскрываемыми блоками.

После выбора примера и кнопки «Новая задача» фокус возвращается в поле цели.
При работе отправка и сохранение защищены от повторов. Журнал инструментов
открыт во время выполнения и автоматически сворачивается после завершения;
его можно раскрыть вручную. Названия операций показаны по-русски, техническое
имя, параметры и фактический результат остаются в подробностях.

## Два воспроизводимых сценария

Примеры в интерфейсе только заполняют цель; запуск выполняется отдельной кнопкой. Примеры используют локальный Day33: он должен присутствовать в checkout. При его отсутствии укажите другой существующий день и не ожидайте анализа отсутствующих файлов.

### Исследование нескольких файлов

> Найди, где используется API поддержки и как вопрос проходит от интерфейса до ответа. Проверь реализацию и тесты.

Ассистент выбирает `list_files`, `search_text` и `read_file`. Покажите реальные пути frontend, backend и тестов, диапазоны прочитанных строк и итоговое объяснение. Ожидаются минимум три различных прочитанных файла. Набор файлов выбирает модель; жёсткого сценария открытия файлов в коде нет.

### Создание документа по коду

> Подготовь памятку для пользователя поддержки Day33: как разбирать проблемы входа в Day30 по данным обращения. Изучи реализацию, интерфейс и тесты и создай Markdown-документ на русском.

После исследования модель вызывает `stage_file`: появится diff, обычно для `day-34/generated/support-guide.md`. До нажатия «Сохранить» файл на диск не записывается. Скачайте patch или сохраните документ кнопкой и откройте созданный файл в редакторе. Повторите задачу с уточнением документа: инструмент может подготовить обновление того же файла. Содержимое и выбор файлов зависят от модели, одинаковый результат между запусками не гарантируется.

Если модель решит, что текст уже подходит, инструмент возвращает `unchanged`; пустое изменение не выдаётся за создание нового файла.

## Что именно автоматизировано

1. Backend передаёт модели цель и JSON-схемы четырёх инструментов.
2. DeepSeek выбирает инструменты и аргументы; backend проверяет их и реально читает файлы.
3. Результаты возвращаются модели с исходными `tool_call_id`, чтения получают серверные ID и SHA256.
4. Модель продолжает исследование или вызывает подготовку документа.
5. Backend строит unified diff и проверяет итоговые ссылки на ID прочитанных источников. JSON-режим включён во всех запросах. Если структура итога неверна, допускается одна отдельная попытка исправить только формат: инструменты отключены, новые файлы не читаются, ID источников проверяются по тем же строгим правилам. Признак `format_repair_attempted` виден в API задачи.
6. При сохранении backend проверяет хеши всех источников и целевых файлов, подготавливает временные файлы и сохраняет весь набор. При обычной ошибке записи уже заменённые файлы восстанавливаются; аварийное завершение процесса между записями не является атомарной транзакцией нескольких файлов.

Итог, источники, фактические вызовы, ошибки инструментов и diff видны отдельно. Обработка занимает несколько запросов к DeepSeek; UI получает состояние через polling. История задач хранится только в памяти процесса, до 30 задач. Перезапуск удаляет историю, сохранённые документы остаются на диске.

## Границы доступа и передаваемые данные

- Корень репозитория фиксирован backend. Модель не получает shell, произвольную запись или запуск кода.
- Читаются только корневой README, `docs/**/*.md`, README дней, публичные backend/frontend/tests/fixtures и Python-исходники общего пакета. Точные правила — `backend/files.py`.
- `.env`, скрытые пути, `.git`, локальная wiki, Memory Bank, данные, зависимости, lock-файлы, видео и транскрипты не входят в область доступа. Символьные ссылки, абсолютные пути и `..` запрещены.
- Текст с подозрительным явным присвоением секрета отклоняется. Эта эвристика не является универсальным поиском секретов: не размещайте секреты в публичных исходниках.
- В DeepSeek уходят цель и прочитанные публичные фрагменты, результаты поиска/списка файлов, сообщения инструментов и создаваемый документ. API-ключ остаётся на backend, в браузер не передаётся.
- Запись разрешена в максимум пять `day-34/generated/<safe-name>.md` за задачу, до 20 KB каждый (до 100 KB суммарно), после чтения минимум трёх разных файлов. Исходники и README других дней не меняются.
- Лимиты: 200 KB на исходный UTF-8 файл; чтение до 200 строк/20 KB за вызов с пагинацией; список до 500 путей, поиск до 100 совпадений; до 10 шагов модели/24 инструментальных вызовов; возможен один дополнительный запрос только для исправления формы итогового JSON. Усечения обозначаются явно. При исчерпании бюджета задача частичная, сохранение недоступно.
- Изменившийся источник или целевой файл вызывает конфликт, вместо перезаписи чужих изменений. Это защита от обычных локальных конфликтов; сервис рассчитан на одного локального пользователя, а не на враждебный параллельный доступ к файловой системе.
- Ошибки DeepSeek видны как ошибки, без подстановки готового ответа и без автоматического повторения сетевого запроса. Форматная корректировка не применяется к сбоям провайдера; второй неверный итог завершает задачу ошибкой. Идентификаторы и хеши подтверждают чтение файлов, но не доказывают правильность смысловых выводов модели.

Сохранённые документы в `generated/` не исключаются из Git: новые файлы и изменения видны в дереве проекта и списке изменений Git. До нажатия «Сохранить изменения» предложение существует только как diff в интерфейсе. Runtime `data/`, ключи, зависимости и сборка остаются исключёнными из Git.

## API

- `GET /api/project` — имя проекта, текущая ветка, область записи и примеры целей.
- `POST /api/tasks` с `{ "goal": "..." }` — запуск, HTTP 202 и ID. Вторая одновременная задача — HTTP 409.
- `GET /api/tasks/{id}` — состояние, итог, источники, trace, diff и метрики.
- `POST /api/tasks/{id}/apply` — сохранение всего набора подготовленных документов. Повторный вызов идемпотентен; конфликт хешей — HTTP 409.
- `GET /api/tasks/{id}/patch` — скачивание общего patch для всех файлов. Состояние задачи содержит `changes` — массив изменений; `change` оставлен как первое изменение для совместимости.

## Проверка

Из корня репозитория:

```bash
PYTHONPATH=day-34 .assistant-venv/bin/python -m pytest day-34/tests -q
cd day-34/frontend
npm test
npm run build
```

Backend-тесты используют реальные временные файлы и контролируемый провайдер для проверки контракта tool loop. Они проверяют запреты путей, symlink, секреты, лимиты чтения/поиска, JSON-схемы, соответствие tool ID, ошибки провайдера, бюджет, создание/обновление/no-op, конфликты источника и назначения, идемпотентность и API. Они не подменяют живую проверку DeepSeek: два сценария выше нужно выполнить с реальным ключом.

## Визуальное сравнение изменений

Предложенные изменения отображаются через `diff2html` 3.4.56: красные строки
с `−` — удалённые, зелёные с `+` — добавленные, рядом показаны номера строк.
Кнопки «Построчно» и «Рядом» переключают единый diff и две колонки «до/после»;
они доступны через Tab и Enter/Space. Изменившиеся части строки выделяются ярче.
Diff раскрывается на полную высоту и прокручивается вместе со страницей. Длинные строки прокручиваются горизонтально внутри панели или своей колонки; высота не ограничена маленьким окном.

«Исходный diff», скачивание patch, Markdown-предпросмотр и исходный текст
до/после сохранены. Отображение ничего не записывает: сохранение остаётся
отдельной кнопкой. При ошибке визуализации выводится исходный diff. HTML из
имён файлов и текста экранируется встроенными шаблонами библиотеки.

Приёмка визуального diff: 26 frontend-тестов и production build прошли.
В браузере проверены настоящий diff замены заголовка и добавления строки,
оба режима, красные/зелёные строки и номера, переключение Enter.
Длинные строки ограничены своими колонками; исходный документ не сохраняли.

## Несколько документов за одну задачу

Например: «Изучи API поддержки Day33, backend, frontend и тесты. Подготовь два
документа: краткий справочник API и чеклист диагностики». Модель сама выбирает
пути в `day-34/generated/` и вызывает `stage_file` для каждого файла.
Интерфейс показывает количество и отдельный diff каждого документа.
Кнопка «Сохранить все изменения» применяет набор, «Скачать общий patch»
содержит все файлы. Повторная подготовка того же пути обновляет его предложение;
no-op удаляет только этот путь из набора. При конфликте любого файла проверка
отклоняет весь набор до записи. Перезапуск backend очищает историю задач в памяти.

Для подготовки файлов лимит одного ответа DeepSeek — 16 000 токенов;
модель получает инструкцию готовить по одному документу за ответ. Для отдельной
попытки исправления итогового JSON лимит — 4 000. Обрезанный ответ считается
ошибкой; автоматического повторения нет.
