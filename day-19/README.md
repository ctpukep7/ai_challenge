# День 19 — композиция MCP-инструментов

Самостоятельный учебный стенд: одно поручение запускает автоматическую цепочку **search → summarize → saveToFile**. LLM выбирает MCP-вызовы, а сервер проверяет порядок и передачу данных. Результат — русская сводка в скачиваемом Markdown-файле.

## Установка и запуск

Нужны Python 3.11+ и Node.js 20+. Команды выполняются из `day-19`:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
npm install
npm --prefix frontend install
cp .env.example .env
```

В локальном `.env` заполните `DEEPSEEK_API_KEY` и `TAVILY_API_KEY`. Не отправляйте ключи в чат и не добавляйте их в Git. Модель по умолчанию — `deepseek-flash`; параметр `DEEPSEEK_MODEL` позволяет выбрать совместимую с tool calls модель DeepSeek.

```bash
npm run dev
```

Интерфейс: [http://127.0.0.1:5185](http://127.0.0.1:5185). API: [http://127.0.0.1:5018](http://127.0.0.1:5018). Без необходимых ключей можно открыть интерфейс и просмотреть историю; запуск объясняет отсутствие настройки.

## Демонстрация

1. Введите, например: «Найди материалы о Model Context Protocol и кратко объясни его назначение».
2. Нажмите **«Запустить»** один раз. Дополнительные подтверждения между инструментами не нужны.
3. На этапе **Поиск** появятся до трёх источников Tavily: названия, ссылки и фрагменты поисковой выдачи. Это не полные страницы сайтов.
4. На этапе **Сводка** агент передаст полученный `search_result_id`; инструмент загрузит именно этот сохранённый набор и вызовет DeepSeek без инструментов.
5. На этапе **Файл** агент передаст `summary_id`; инструмент сохранит подготовленный Markdown в UTF-8.
6. Откройте подробности MCP: проверьте фактические вызовы, идентификаторы и hashes. Нажмите **«Скачать Markdown»**.

Кнопки примеров только заполняют поле; запуск выполняется отдельно. На узком экране этапы располагаются вертикально. История сохраняется в SQLite и доступна после обновления страницы.

## JSON и детали каждого этапа

Нажмите **«JSON и детали»** в карточке поиска, сводки или сохранения. Под этапами
откроется панель с входами, результатами и передачей данных; повторное нажатие
закроет её. JSON-блоки раскрываются отдельно.

- **Поиск:** параметры MCP `tools/call`, запрос Tavily, полученные фрагменты
  и структурированный результат с `search_result_id`.
- **Сводка:** запрос агента к DeepSeek, MCP-вызов с ID поиска, сохранённый
  набор источников и отдельный запрос DeepSeek без инструментов для сводки.
- **Файл:** MCP-вызов с `summary_id`, загруженный Markdown и квитанция
  автоматического сохранения с размером и SHA-256.

Показываются тела фактически выполненных запросов и нормализованные ответы.
Авторизация, ключи, reasoning и сырые ошибки провайдеров не записываются.
MCP-блок содержит параметры SDK и структурированный ответ; transport ID
JSON-RPC не подменяется идентификатором `tool_call_id` модели.

В старых запусках можно посмотреть параметры из trace и сохранённые результаты.
HTTP-обмены для них не восстанавливаются: расширенная запись начинается с новых
запусков. Статус **«Файл сохранён на сервере»** подтверждает автоматическое
завершение цепочки; кнопка скачивания получает уже готовый файл на компьютер.

## Как доказывается передача данных

`search` сохраняет неизменяемый набор источников. `summarize` принимает его ID, а не текст, пересоставленный моделью. Результат сводки хранит родительский ID и входной SHA-256. `saveToFile` принимает только ID сводки и записывает её точные байты: SHA-256 файла совпадает с hash Markdown.

Каждый ID принадлежит конкретному запуску. Чужие и неизвестные ID, пропуск этапа и подмена уже сохранённого результата отклоняются. Статус **«Готово»** определяется зарегистрированным файлом и проверкой его hash. Свободный ответ модели «файл сохранён» сам по себе ничего не подтверждает.

Эти проверки доказывают происхождение данных и точность записи. Они не гарантируют фактологическую точность генеративной сводки — её нужно сверять с источниками.

## Композиция инструментов в Day 18

В [Day 18 — планировщик и фоновые задачи](../day-18/README.md) тоже есть
автоматическая композиция MCP. Полный сценарий включает две связанные цепочки:

1. **Создание задания в чате:** `load_skill → resolve_city → create_weather_schedule`.
   Агент загружает инструкцию, находит город через геокодинг Open-Meteo и передаёт
   полученный `city_id` в создание расписания. Сервер сохраняет выбранный город,
   его координаты и периодичность в SQLite.
2. **Каждый сбор по расписанию:** `get_current_weather → save_weather_result`.
   Первый инструмент получает погоду по сохранённым координатам и возвращает
   `result_id`; второй сохраняет наблюдение по этому ID. Сервер отклоняет неизвестный
   ID или результат другого запуска, а успех подтверждает сохранённой записью.

Поиск города выполняется при настройке задания; повторные сборы используют
сохранённые координаты. Поэтому все пять вызовов относятся к полному сценарию,
а отдельный фоновый запуск содержит два вызова. Порядок описан в skill,
инструменты выбирает LLM и вызывает настоящий MCP-клиент. Обе цепочки и передачу
ID можно посмотреть в действиях агента и «JSON-запросах» чата и фоновых запусков.
Day 19 развивает эту логику отдельным этапом суммаризации и сохранением
проверяемого Markdown-файла.

## Устройство и ограничения

```text
Vue → FastAPI → DeepSeek-агент → MCP ClientSession (stdio)
                              → search / summarize / saveToFile
                              → SQLite + локальный Markdown
```

На запуск создаётся отдельный MCP-процесс. Реально выполняются `initialize`, `tools/list` и `tools/call`; schemas берутся из discovery. Сервер объявляет ровно три инструмента и возвращает structured outputs. STDOUT процесса занят протоколом MCP.

Поиск обращается к Tavily с `search_depth=basic`, `max_results=3`, `include_answer=false`, `include_raw_content=false`. Поручение и поисковый запрос передаются внешним провайдерам; найденные фрагменты используются DeepSeek для сводки. Ключи остаются на Python-стороне и не входят в результаты, trace или файл.

Лимиты: поручение 2000 символов, query 400, фрагмент 3000, готовый Markdown 10 000. Запуск ограничен 120 секундами и шестью решениями модели; поиск — 15 секундами, отдельный LLM-вызов — 25. Допускается одна коррекция ошибочных аргументов, скрытых сетевых повторов нет.

Одновременно выполняется один запуск. Повтор с тем же UUID и поручением возвращает существующий запуск; другой текст с этим UUID или новый запуск во время выполнения получает 409. Незавершённые запуски после перезапуска становятся прерванными и не возобновляются автоматически.

Пустая выдача, ошибка сети/провайдера/схемы, раннее завершение агента и ошибка записи останавливают цепочку на соответствующем этапе. Частичные результаты остаются доступны. Демонстрационных результатов вместо сетевой ошибки нет.

Локальные данные: `data/pipeline.sqlite3` и `data/files/`. Имя файла выбирает сервер, пользователь и модель не передают произвольные пути. `.env`, базы, файлы результатов, окружения и сборки исключены из Git. Расписаний, профилей и универсального filesystem MCP в этом дне нет.

В Git входят исходники, тесты, README, lock-файлы и `.env.example` с пустыми
ключами. Настоящие `.env` и их локальные варианты, данные запусков и JSON-журналы,
базы SQLite с WAL/SHM, логи и демонстрационные видео остаются локальными.
Не добавляйте исключённые файлы через `git add -f`.

## API

- `POST /api/runs` — `{prompt, request_id}`; 202 и ID запуска.
- `GET /api/runs/{run_id}` — статус, этапы, trace, результаты и журнал `exchanges` новых запусков.
- `GET /api/runs/{run_id}/download` — зарегистрированный Markdown с проверкой hash.
- `GET /api/state` — наличие настроек без значений ключей и последние десять запусков.

## Проверки

```bash
npm test
npm run build
```

Автоматические тесты используют временные базы и fake HTTP/LLM-адаптеры. Они проверяют реальные MCP-сессии, последовательность вызовов, точную передачу данных, скачивание, повторные запросы, неправильные ID, ошибки и ограничения. Отдельная stdio-проверка проверяет discovery настоящего subprocess.

Live-проверка требует обоих настроенных ключей и доступности Tavily/DeepSeek. Успешный прогон засчитывается только после реального поиска и сохранения файла; тесты с подменёнными провайдерами не являются live-проверкой.

Проверено 26 сентября 2026: 65 тестов, production build, единый запуск и браузерные сценарии на desktop и узком экране. Discovery проверен через настоящий stdio-процесс; автоматическая цепочка и точные байты download — через настоящие MCP-сессии с тестовыми провайдерами. После добавления JSON-деталей выполнен успешный live-прогон Tavily + DeepSeek: три источника, три последовательных инструмента, девять записанных обменов, Markdown 4817 байт. Проверены реальные тела запросов, связи `tool_call_id`, исключение ключей и reasoning, входной hash сводки и совпадение скачанных байтов со сводкой. В браузере раскрыты JSON всех трёх этапов, проверено честное представление старых запусков и отсутствие горизонтального переполнения на экране шириной 391 CSS-пиксель.
