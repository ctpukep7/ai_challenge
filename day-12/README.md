# День 12 — персонализированный агент

Самостоятельный учебный стенд: явный пользовательский профиль подключается к каждому запросу поверх трёхслойной памяти. Профиль меняет подачу, но не получает права отменять safety или ограничения задачи.

## Что демонстрирует урок

- **Профиль** — сохранённые defaults для языка, тона, глубины и формата ответа.
- **Краткосрочная память** — отдельные диалоги каждого профиля. При переключении восстанавливается последний выбранный диалог этого профиля.
- **Рабочая память** — общая текущая задача: цель, данные, hard constraints, вопросы.
- **Долговременная память** — общие явно сохранённые решения и знания.
- Ничего не извлекается из разговора в профиль автоматически. Создание, редактирование и переключение происходят только по явному действию пользователя.

После первого запуска или полного сброса создаётся один профиль:

1. «Новичок» — простые термины, шаги и пример.

Остальные профили пользователь создаёт сам. В окне создания есть шаблоны «Эксперт» и «Руководитель»: отдельная кнопка только заполняет форму подходящими настройками, после чего значения можно изменить и явно подтвердить кнопкой «Создать и активировать».

## Запуск

Требуются Python 3.11+ и Node.js 20+.

```bash
cd day-12
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
npm install
npm --prefix frontend install
cp .env.example .env
```

Добавьте в `.env` ключ нужного провайдера, затем:

```bash
npm run dev
```

- интерфейс: `http://localhost:5178`
- API: `http://localhost:5011`

Файл `.env`, база SQLite, окружение Python и сборка исключены из Git.

## Архитектура и порядок контекста

Backend — FastAPI + SQLite, frontend — Vue 3 + Vite. `user_profiles` хранит до десяти профилей. `sessions.profile_id` связывает сессии с профилями; частичный уникальный индекс оставляет ровно одну выбранную сессию на профиль. Рабочая задача и `long_term_entries` намеренно не имеют `profile_id` и поэтому общие.

Каждый основной запрос собирается строго так:

1. неизменяемые константы и safety;
2. отдельный `ACTIVE_PROFILE_DATA` system-блок с JSON snapshot активного профиля и границей недоверенных данных;
3. общие decisions/knowledge;
4. общая рабочая задача;
5. история только активной профильной сессии с выбранным режимом сжатия;
6. текущий вопрос.

`tone`, `detail_level` и `response_format` — настройки по умолчанию. Безопасная явная просьба в текущем вопросе может разово изменить стиль. Profile constraints не могут отменить safety или hard constraints. Точный snapshot профиля сохраняется в preview каждого ответа.

Поддержаны режимы контекста: полная сессия, Sliding Window, Sticky Facts, Rolling Summary и только явная память. Ветки, summaries и Sticky Facts копируются или обновляются только внутри профильной сессии.

## API

- `GET /api/state` — профили, активный профиль, его сессии, общая память, безопасный аудит и метрики.
- `POST /api/profiles` — создать и сразу активировать профиль.
- `PUT /api/profiles/{id}` — явно обновить профиль.
- `POST /api/profiles/{id}/activate` — переключить профиль и восстановить его выбранную сессию.
- `POST /api/sessions`, `/api/sessions/{id}/activate|reset|branch` — управление диалогами только активного профиля.
- `DELETE /api/sessions/{id}` — удалить диалог активного профиля вместе с сообщениями и производными summaries/facts. После удаления активным становится последний оставшийся диалог; вместо последнего удалённого создаётся новый пустой «Диалог 1».
- `PUT /api/task`, `POST|DELETE /api/long-term` — общая явная память.
- `POST /api/ask` — запрос к агенту.
- `POST /api/memory/clear` — полный сброс профилей и всех слоёв памяти с созданием одного профиля «Новичок» и одной пустой сессии. Действие доступно в опасной зоне окна «Настройки».

Все поля профиля ограничены 500 символами, имя — 80; секреты и API-ключи отклоняются. Аудит персонализации хранит только тип действия и id, без содержимого полей. Markdown ответов очищается перед отображением.

## Сценарий видео на 3 минуты

1. В профиле «Новичок» выберите один из двух тестов: **«Объяснить RAG»** подставляет вопрос `Объясни, что такое RAG, когда он нужен и какие у него риски.`, а **«Выбрать подход»** предлагает сравнить RAG, fine-tuning и поиск без LLM для ежедневно обновляемой базы поддержки. Обе кнопки только заполняют поле и ничего не отправляют.
2. Отправьте выбранный вопрос. Покажите пошаговый простой ответ и откройте «Контекст ответа»: в preview сохранён snapshot «Новичка».
3. Нажмите **＋** рядом с профилями, выберите шаблон «Эксперт» и нажмите **«Заполнить шаблоном»**. Покажите, что поля заполнились, но профиль ещё не создан.
4. При необходимости измените поля и отдельно нажмите **«Создать и активировать»**. Новый профиль получит пустой диалог.
5. Повторите тот же выбранный вопрос — ответ станет глубже. Затем сравните профили и на втором тестовом вопросе. Вернитесь к «Новичку»: восстановится его собственная история.
6. Создайте и удалите дополнительный диалог. Затем откройте «Настройки» и покажите отдельную опасную зону полного сброса, не подтверждая удаление во время демонстрации.

Главная мысль: **одни данные + одинаковый выбранный вопрос + разные явные профили = разные полезные ответы, без смешивания разговоров**.

## Проверка

```bash
source .venv/bin/activate
npm test
npm run build
```

Тесты проверяют единственный стартовый профиль, лимиты, CRUD/переключение профилей, порядок контекста, изоляцию диалогов и компрессии, удаление активной/неактивной/последней/чужой сессии, каскадную очистку данных сессии, полный сброс, общую память, profile snapshot, атомарность хода при ошибке провайдера, отсутствие ключей и очистку Markdown.
