# День 25 — мини-чат с RAG и памятью задачи

Чат сохраняет историю и память задачи в SQLite. Каждый новый вопрос запускает
новый поиск по README проекта; ответ использует найденный контекст и проходит
проверку цитат и смысла из Day 24. Источники показаны у каждого фактического
ответа. При недостаточных доказательствах чат говорит «Не знаю» и просит уточнить.

## Запуск

Нужны Python 3.12, Node.js 20+ и Git. Из каталога `day-25`:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
npm --prefix frontend ci
cp .env.example .env
# Заполните DEEPSEEK_API_KEY только в локальном .env
npm run dev
```

[Интерфейс localhost:5191](http://127.0.0.1:5191/),
[API localhost:5024/docs](http://127.0.0.1:5024/docs).
Остановка — `Ctrl+C`; оба сервера слушают localhost.
Нужны библиотечные файлы дней 21 и 24 из этого checkout;
запускать их серверы не требуется.

## Источники и две базы

Корпус — tracked README корня и дней 01–20, без приватных документов,
локальных отчётов и README самих RAG-дней. `data/index.sqlite` хранит собственный
векторный индекс, `data/chat.sqlite` — сессии, сообщения, память и результаты.
Удаление сессии не очищает индекс. Изменение README требует пересборки индекса,
но не уничтожает историю. Первое построение загружает FastEmbed-модель;
дальнейшее извлечение локальное. Полный текст истории сохраняется между запусками.

## Память задачи

У каждой сессии свои цель, уточнения, ограничения, термины и выбранные дни.
Память собирается автоматически из обычной беседы: не нужно произносить
«Цель:», «Уточнение:» или заполнять каждое поле. Например, сообщение
«Хочу разобраться в Day 07, объясняй кратко без кода» задаёт тему и ограничение;
следующее «Меня интересует одна выбранная сессия» добавляет уточнение.

Отдельный вызов DeepSeek предлагает структурированные изменения памяти,
основанные на сообщениях пользователя. В интерфейсе показаны сохранённая
память и изменения с фрагментами сообщения, на которые они опираются.
Ответы ассистента не становятся пользовательскими фактами. Извлечение может
ошибиться: необязательная панель позволяет вручную исправить память.
При ошибке извлечения прежняя память сохраняется, показывается предупреждение.
Явные команды с префиксами остаются дополнительным способом исправления.

Для ответа передаются новый вопрос, последние 12 сообщений user/assistant
и память задачи.
История хранится полностью, но не целиком передаётся на каждый запрос.
Короткое продолжение получает контекст текущей темы. Явное указание нового дня
в вопросе имеет приоритет над прежним контекстом поиска. На экране виден
фактический поисковый запрос и выбранные источники.

Сессии изолированы. Ревизия и идентификатор запроса защищают от устаревшей записи
и повторной отправки; медленный HTTP-вызов не держит SQLite write-транзакцию.
Ошибка не превращается в успешный фактический ответ. Память и история остаются
доступными после перезапуска.

## Ответы с источниками

Day 24 предоставляет общий grounding-контракт: каждое утверждение связано с
точной цитатой из явно отобранного контекста. Сервер восстанавливает `source`,
`section` и `chunk_id`, проверяет текст цитаты, затем отдельный verifier
проверяет смысл утверждения.

В Day 25 контекст включает прошедшие порог опорные чанки, ограниченное окно
соседей с ролью `neighbor` и не более двух дополнительных чанков по совпадениям
слов с ролью `lexical_context`. Дополнительные чанки берутся только из источника
уже найденного опорного чанка, имеют настоящие ID и указывают `anchor_chunk_id`.
Они показываются отдельно: `score=null`, cosine для них не вычислялся.
Это помогает найти отдельное определение или факт в другом разделе того же
README. Если ни один опорный чанк не прошёл порог, такое расширение не
выполняется: слабый контекст по-прежнему приводит к отказу.

Для смешанного результата смысловой проверки публикуются только утверждения
со статусом `supported`. Остальные исключаются и видны отдельно в раскрываемой
диагностике. Частичный ответ явно помечается; его полнота не гарантируется.
Если подтверждённых утверждений нет или не пройдены проверки цитат/формата,
чат говорит «Не знаю» с уточнением. Отказ показывает отсутствие подтверждённых
источников; служебное изменение памяти не считается RAG-ответом с цитатами.
Проверяющая модель может ошибаться — точная цитата не доказывает смысловую
правильность ответа автоматически. Наличие источника не является гарантией
полного ответа на все части вопроса.

## Два длинных сценария

`scenarios.json` содержит два сценария по 15 пользовательских сообщений.
Они проверяют удержание цели, уточнения, ограничения, короткие продолжения,
смену источника и ссылки у фактических ответов.

Выберите свой диалог и сценарий. Кнопка **«Подставить следующий вопрос»** только
заполняет обычное поле сообщения: HTTP-запрос и вызов LLM не выполняются.
Текст можно изменить; отправка происходит только после нажатия
**«Отправить вопрос»**. После ответа снова нажмите подстановку, затем отправку.
Следующий вопрос не подставляется, пока подготовленный не отправлен; счётчик
показывает число отправленных вопросов. Смена сценария или диалога сбрасывает
локальный счётчик и маркер подготовленного вопроса.

Ответ «Не знаю» или сохранённая ошибка обработки тоже считаются отправленным
сообщением. При транспортной ошибке вопрос остаётся в поле, шаг не продвигается
и доступна повторная отправка. Обычный вопрос вне сценария не меняет счётчик.
Новые сценарии не создают отдельные сессии автоматически и не используют таймер
между вопросами. Память и история обновляются в выбранном диалоге; export
диалога позволяет проверить сообщения, источники и память.

Если автоматический прогон был запущен в прежней версии, интерфейс продолжает
показывать его ход и позволяет остановить. Нового автопрогона кнопки не запускают.
На время такого старого прогона ручное изменение его сессии заблокировано.

## Демонстрация без голоса

1. Покажите готовый индекс и создайте новую сессию.
2. Начните обычным вопросом, упомянув интересующую тему и желаемый стиль — покажите автоматически собранную память.
3. Задайте вопрос по конкретному дню, раскройте поиск, цитаты и источники.
4. Задайте короткое продолжение без повторения цели.
5. Смените тему явным номером дня и проверьте следующее продолжение.
6. Переключитесь между сессиями: у каждой своя история и память.
7. Обновите страницу — история и память сохранятся.
8. Пройдите оба сценария через подстановку и обычную отправку, затем экспортируйте диалог.

## Данные, проверки и ограничения

Внешнему DeepSeek передаются вопрос, ограниченная история, память задачи
и выбранные README-фрагменты; ключ остаётся на backend. Базы, `.env`, кэш,
виртуальное окружение, сборка и экспорт не коммитятся. Чат не имеет
многопользовательской авторизации; это локальная учебная реализация.

```sh
.venv/bin/python -m pytest tests
npm run test:frontend
npm run build
```

Локальные тесты проверяют persistence, изоляцию, ревизии, повтор запросов,
свежий поиск и память в длинных сценариях. Fake-LLM тестов не заменяет живую
проверку: её результаты фиксируются отдельно после выполнения.

Первичные источники: [SQLite — isolation](https://www.sqlite.org/isolation.html),
[Anthropic — reducing hallucinations](https://platform.claude.com/docs/en/test-and-evaluate/strengthen-guardrails/reduce-hallucinations).

### Запуск одного экземпляра

Запуск рассчитан на macOS/Linux и один backend-процесс на базу чата.
На startup приложение получает эксклюзивную файловую блокировку и только
затем помечает старые pending-запросы как interrupted. Второй сервер с той
же базой не запускается; импорт модуля и чтение базы активные запросы не
прерывают. При остановке блокировка освобождается. Не запускайте несколько
uvicorn workers на одну базу.

Полные сообщения и ответы живут в SQLite; записи interrupted доступны для
повторной отправки с новым request_id. Фоновые объекты прогонов живут в памяти
процесса и исчезают после рестарта, поэтому export следует сохранить заранее.
Чат-сессия сценария сохраняется в SQLite независимо от этого объекта.

## Разнообразные сценарии для записи

Готовые сценарии содержат по 15 обычных вопросов, без команд памяти:

- **«От чата до агента с инструментами»** — цель подготовить демонстрацию
  возможностей ассистента. Вопросы переходят от истории и токенов к summary,
  слоям памяти, профилям, MCP, расписаниям и проверяемым результатам.
- **«Управляемая задача с внешними инструментами»** — цель разобраться в
  серверных гарантиях. Вопросы о guards, checkpoint, preflight, подтверждении
  календаря, арендах, транспорте MCP и границах доказательств.

Первый сценарий использует 12 разных README, второй — 8. Каждый вопрос
проверяет новый факт; один источник встречается подряд не более двух раз.
Тема меняется явным номером дня, а короткие продолжения используют предыдущую
тему. Цель и ограничения остаются общими: в середине беседы пользователь
естественно уточняет область задачи, меняет желаемую подробность и определяет
термин. Это проверяет накопление памяти без повторения одного ответа.

Для ручной записи можно пройти первый сценарий в своём диалоге:

1. `Хочу подготовить демонстрацию возможностей учебного AI-ассистента. Объясняй кратко, без кода, по README. Как в Day 07 сохраняется история диалога?`
2. `А при ошибке API новый вопрос попадёт в эту историю?`
3. `Чтобы показать расход ресурсов, перейдём к Day 08. Чем prompt_tokens отличается от completion_tokens?`
4. `Теперь про длинный разговор: как rolling-summary в Day 09 заменяет старые сообщения?`
5. `В Day 10 можно обойтись без summary. Какие сообщения отправляет Sliding Window?`
6. `Уточню цель: показываем возможности пользователя, а не установку проекта. Какие три слоя памяти представлены в Day 11?`
7. `Теперь можно объяснять чуть подробнее, но всё ещё без кода. Что профиль Day 12 меняет в подаче ответа?`
8. `Для нашей демонстрации надо отделить агент от памяти. Есть ли у AssistantAgent Day 06 собственная история или инструменты?`
9. `Перейдём к инструментам: как Day 16 сначала согласует протокол MCP и получает каталог tools?`
10. `Назовём inputSchema схемой аргументов инструмента. Что она описывает в найденном каталоге?`
11. `Для фоновой работы посмотрим Day 18. Чем системный cron отличается от расписаний в SQLite?`
12. `У агента с несколькими серверами Day 20 могут совпадать имена инструментов. Как реестр различает такие имена?`
13. `Для демонстрации полезен итоговый файл. Как Day 19 проверяет, что скачиваемый Markdown соответствует сохранённой квитанции?`
14. `Покажем действие пользователя в Day 17: сколько времени действительно предложение создать событие?`
15. `Вернёмся к измерению ресурсов, сохранив цель демонстрации. В Day 08 синтетические копии истории сохраняются в SQLite или существуют только в запросе?`

После шага 6 покажите автоматически собранную цель, ограничение и уточнение.
Обновите страницу и продолжите тот же диалог. После шага 10 покажите новый
термин и изменённую подробность ответа. У одного ответа раскройте источники,
цитаты, изменения памяти и реальный запрос с `task_state`.

Факты и формулировки сверены с README. Новая версия сценариев требует
отдельного полного живого прогона; исторические показатели выше к ней не
относятся. Нет гарантии, что каждый ответ будет подтверждён: при недостаточных
доказательствах допустим отказ. Для записи нажимайте «Подставить следующий вопрос», проверяйте текст в поле
сообщения и отправляйте его обычной кнопкой. Реальный ответ и обновлённая
память появляются по мере готовности; момент следующего вопроса выбираете вы.

### Удаление диалогов

Кнопка × возле названия удаляет один диалог, кнопка «Удалить все диалоги» —
весь список. Перед удалением показывается подтверждение. История и память
удаляются вместе с диалогом, индекс README остаётся. Во время активного
автопрогона его сессию удалить нельзя; массовое удаление недоступно до
остановки прогона. Незавершённые запросы проверяются перед удалением.
